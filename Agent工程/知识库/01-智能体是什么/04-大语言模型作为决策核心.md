# 大语言模型作为决策核心

## 定位

本节回答：大语言模型为智能体提供了哪些能力、这些能力从哪里来，又带来哪些局限，以及选型时需要看哪些维度。模型内部的架构（Transformer、注意力机制等，教材 3.1）属于模型本身的知识，本节不展开。

前置：[智能体的定义与构成](node:agentdef)。文中的“框架”指模型之外、驱动循环运行的那层程序，见[模型与框架的职责边界](node:responsibility)。

文中的“教材”指核心材料 Hello-Agents，小节号（如 2.4.5）为教材的章节编号；引用写法与版本见[参考资料](node:refs)。

## 核心解释

**能力从哪里来。** 教材给出三条（3.2.1、3.3.1）：

- **缩放法则**：模型性能与参数量、训练数据量、计算量之间存在可预测的幂律关系；Chinchilla 定律进一步指出，在给定计算预算下，参数量与数据量存在最优配比，模型可以更小但需要多得多的数据。
- **能力涌现**：当规模跨过某个阈值，模型会展现出小规模模型不具备的能力——链式思考、指令遵循、多步推理、代码生成。教材由此给出一条对智能体开发者的直接结论：选择一个足够规模的模型，是实现复杂自主决策和规划能力的前提。
- **指令调优**：早期模型主要做文本补全，需要用少样本示例“教会”它做什么；经过指令调优的模型能够理解并遵循指令，直接下达清晰的自然语言指令才成为可能。

对智能体来说，模型承担的是三件事：把目标分解成步骤（规划）、在给定的工具描述下选出下一步调用（决策）、把返回的观察整合进下一步推理（理解）〔待核验，归纳由本板块整理〕。三件事都发生在“给定输入之后”，因此模型能做到什么，取决于框架给了它什么输入。

**两个必须知道的约束。**

- **词元与上下文窗口**：文本先由分词器切成词元（3.2.2），模型一次能处理的词元数有上限。教材把上下文窗口单列为选型维度，并指出需要理解长文档、分析代码库或维持长期记忆的智能体，需要较大的上下文窗口（3.2.4）。[工具结果处理](node:toolresult)与上下文工程的全部取舍，都来自这个上限。
- **采样参数**：温度控制输出的随机性，温度越低输出越确定、重复率越高，温度越高越发散；Top-k 与 Top-p 则限制候选词元的集合（3.2.1）。教材在调试 ReAct 智能体时建议把温度设为 0 以保证输出的确定性（4.2.4）。同一输入可能得到不同输出，这是[任务评估](node:taskeval)必须重复运行的直接原因。

**局限。** 教材列出三类（3.3.2）：

| 局限 | 教材的说明 | 在智能体里的表现 |
|---|---|---|
| 幻觉 | 分为事实性、忠实性与内在幻觉；成因包括训练数据含错误信息、自回归生成没有内置事实核查、复杂推理中逻辑出错 | 教材举例：旅游规划智能体可能推荐现实中不存在的景点，或给出航班号错误的机票 |
| 知识时效性不足 | 模型掌握的知识截止于训练数据收集的时点 | 新事件、新概念需要通过检索或工具获取 |
| 偏见 | 训练数据中的偏见与刻板印象会被模型吸收并反映出来 | 面向公众或涉及敏感信息的应用需要在选型时评估 |

教材把缓解手段分成三层：数据层面（清洗、引入事实性知识、基于人类反馈的强化学习）、模型层面（新架构、让模型表达不确定性）、推理与生成层面（检索增强生成、多步推理与验证、引入外部工具）（3.3.2）。第三层的三条，恰好就是智能体的三个基本构件——检索、反思、工具调用。换句话说，智能体这套结构本身，很大程度上就是对模型局限的工程回应〔待核验〕。

**选型维度**（3.2.4）：性能与能力、成本、速度（延迟）、上下文窗口、部署方式、生态与工具链、可微调性、安全性与伦理。教材同时提醒，模型版本与性能数据变化很快，选型原则比具体型号更重要。

## 机制深挖

### 模型差异如何传导到智能体

教材有两处可观察的例子。其一，使用自定义工具调用格式的 SimpleAgent，在复杂场景下的表现可能不如使用原生函数调用的智能体（12.2.6）。其二，并非所有模型都能持续稳定地遵循预设格式，提示词模板中的微小变动都可能影响模型行为（4.2.4）。

因此“换一个更强的模型”与“改一处框架实现”是两类不同的改动，各自改变什么、不改变什么，见[模型与框架的职责边界](node:responsibility)。

### 涌现能力与提示方式的对应

上下文学习让模型无需调整权重，仅靠输入中的零个或几个示例就能完成新任务；思维链让模型在回答复杂问题前先输出推理过程，可显著提升逻辑、算术与常识推理的准确性（2.4.3、3.3.1）。

ReAct 这类范式正建立在这两项能力之上：它要求模型每一轮先写出 `Thought` 再给出 `Action`（4.2），这既是思维链的应用，也让框架得以从输出中解析出结构〔待核验，这一因果关系由本板块整理〕。

### 温度设置的两难

调试时把温度设为 0 能让问题可复现（4.2.4），但生产环境未必使用同样的设置；用温度 0 调好的提示词，在实际采样参数下不一定同样稳定〔待核验〕。这也是评估要覆盖真实设置的原因，见[评估设计四要素](node:evaldesign)。

## 实验与原文
