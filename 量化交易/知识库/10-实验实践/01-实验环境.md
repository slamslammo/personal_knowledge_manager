# 实验环境

量化实验不仅要“在当前电脑上跑通”，还要能说明使用了什么 Python、什么库、什么数据源，并在以后尽可能复现同一结果。本项目用 `environment.yml` 定义名为 `pkm-quant` 的独立环境，避免与系统 Python 或其他项目互相污染。

## 工具链分层

| 层次 | 当前工具 | 作用 |
|---|---|---|
| 环境管理 | Miniforge / Conda | 创建隔离环境，统一管理 Python 和需要编译的科学计算依赖。 |
| 语言运行时 | Python 3.11 | 执行数据处理、研究、回测和可视化代码。 |
| Python 包管理 | pip | 安装 PyPI 上更新更及时或 Conda 当前无法完整求解的包。 |
| 交互研究 | JupyterLab | 把代码、图表、公式、观察和结论放在同一份 Notebook 中。 |
| 内核连接 | ipykernel | 让 Jupyter Notebook 真正使用 `pkm-quant` 中的 Python。 |
| 项目定义 | `environment.yml` | 声明依赖来源与固定版本，用于重建和同步环境。 |
| 环境验收 | `实验/scripts/check_environment.py` | 检查核心库导入、版本和本地绘图能力，不依赖外部行情服务。 |

Notebook 所显示的内核名称不等同于当前终端环境。遇到“终端能导入、Notebook 不能导入”时，应先在 Notebook 中检查：

```python
import sys
print(sys.executable)
```

本项目应指向：

```text
/opt/homebrew/Caskroom/miniforge/base/envs/pkm-quant/bin/python
```

## Conda、conda-forge 与 Miniforge

这三个名称处于不同层次：

| 名称 | 它是什么 | 本项目中的职责 |
|---|---|---|
| Conda | 环境管理器和包管理器 | 创建 `pkm-quant`、解析依赖、安装/更新包、切换环境。 |
| conda-forge | 社区维护的 Conda 软件包渠道 | 提供适用于不同操作系统和 CPU 架构的预编译软件包及其依赖元数据。 |
| Miniforge | 预配置 conda-forge 的轻量 Conda 发行方式 | 在本机提供 `conda` / `mamba` 命令，并默认只使用 conda-forge。 |
| pip / PyPI | Python 官方生态的包安装工具与包索引 | 在 `pkm-quant` 内补充 Conda 当前无法完整提供或需要更新版本的 Python 包。 |

conda-forge 不是另一个 Python，也不是安装命令。可以把它理解为 Conda 获取软件包的“仓库渠道”：社区维护者编写构建配方，经持续集成构建出 macOS、Linux、Windows 等平台的软件包，再发布到 conda-forge channel。Conda 会读取 channel 的包索引和依赖信息，而不是现场从源码编译每一个科学计算库。

本机当前配置是：

| 配置 | 当前值 | 含义 |
|---|---|---|
| Conda 发行方式 | Miniforge | 基础环境位于 `/opt/homebrew/Caskroom/miniforge/base`。 |
| Conda 版本 | 26.3.2 | 执行环境和包管理。 |
| 依赖求解器 | libmamba | 计算哪些包版本能够同时满足所有约束。 |
| 平台 | `osx-arm64` | Apple Silicon 的 macOS 包。 |
| Channel | `conda-forge` | 同时查询 `osx-arm64` 平台包和 `noarch` 跨平台包。 |
| Channel priority | `flexible` | 当前只有一个 channel，不会发生跨渠道混装；增加其他 channel 时应改为 `strict`。 |

不要把 conda-forge 与 Anaconda 的 `defaults` 渠道随意混合。不同渠道可能使用不同的编译工具链和依赖组合；如果以后必须增加渠道，应记录顺序并设置严格优先级：

```bash
conda config --set channel_priority strict
conda config --show channels channel_priority
```

## 本项目的安装部署流程

`environment.yml` 是安装入口，其中四类信息分别表示：

| 字段 | 当前含义 |
|---|---|
| `name: pkm-quant` | 创建或同步的环境名称。 |
| `channels: [conda-forge]` | Conda 去哪里查询软件包和依赖元数据。 |
| `dependencies` 中的普通条目 | 先由 Conda 求解并安装，例如 Python、NumPy、pandas、JupyterLab。 |
| `dependencies` 中的 `pip` 子列表 | Conda 阶段完成后，再调用该环境自己的 pip 安装，例如 yfinance 和 AkShare。 |

执行 `conda env create -f environment.yml` 时，实际过程是：

```text
读取 environment.yml
        ↓
确定环境名、平台、channel 和版本约束
        ↓
从 conda-forge 读取 osx-arm64 / noarch 包索引
        ↓
libmamba 计算一组互相兼容的包版本
        ↓
下载、校验并提交 Conda 包事务
        ↓
调用 pkm-quant/bin/python -m pip 安装 pip 子列表
        ↓
环境创建完成
        ↓
注册 ipykernel → 本地验收 → 外部数据低频验收
```

几个关键点：

- **依赖求解**不是简单地给每个库取最新版，而是寻找一组全部约束都能满足的版本；缺少某个依赖时可能回退到旧版。
- **Conda 阶段先于 pip 阶段**。Conda 不会自动用 PyPI 的包去满足某个 Conda 包缺失的依赖，因此 yfinance 必须整体放到 pip 子列表。
- **激活环境**只会调整当前终端的命令路径，不会自动修改已有 Notebook 的内核。
- **注册内核**把环境暴露给 Jupyter，但不会重新安装依赖。
- **`--prune` 同步**会清理不再由环境定义需要的 Conda 包，使用前应确保重要依赖已写入 `environment.yml`。
- **验收与安装分开**：安装命令退出成功后仍要检查实际版本、导入、绘图和依赖冲突；行情请求属于第二层外部验收。

可以用以下命令查看安装来源：

```bash
conda list -n pkm-quant --show-channel-urls
```

输出中的 `conda-forge` 表示由 Conda channel 管理，`pypi` 表示由该环境中的 pip 安装。两者可以在同一个环境中共存，但同一个包应尽量只交给其中一种工具管理。

## 为什么同时使用 Conda 和 pip

本项目优先由 Conda 安装 Python、NumPy、pandas、SciPy、Matplotlib、scikit-learn、JupyterLab 等基础包，因为它擅长处理 macOS ARM64 上的二进制依赖。pip 只负责当前需要从 PyPI 安装的包。

如果在 Conda 依赖区只写未固定版本的 `yfinance`，当前 `osx-arm64` 求解器会选择 0.2.57。原因不是该版本被课程指定，而是 yfinance 从 0.2.58 开始依赖 `curl-cffi`，Conda 当前渠道缺少该依赖，于是回退到最后一个可解版本。项目因此在 pip 区显式安装 `curl_cffi`，并固定 `yfinance==1.5.1`。

原则是：**先让 Conda 解决基础科学计算栈，再由同一环境中的 pip 补充少数包；不要交替随意安装同一个包。**

## 创建与同步环境

首次创建：

```bash
cd "/Users/mojiawen/Documents/personal_knowledge_manager/量化交易"
conda env create -f environment.yml
conda activate pkm-quant
```

同步已经存在的环境：

```bash
conda env update -n pkm-quant -f environment.yml --prune
conda activate pkm-quant
```

注册 Jupyter 内核：

```bash
python -m ipykernel install \
  --user \
  --name pkm-quant \
  --display-name "Python (pkm-quant)"
```

启动 JupyterLab 后，应在 Notebook 右上角选择 `Python (pkm-quant)`。

## 环境验收

```bash
conda activate pkm-quant
python 实验/scripts/check_environment.py
python -m pip check
jupyter kernelspec list
```

验收分为两个层次：

1. **本地环境验收**：核心库能导入、版本符合预期、Matplotlib 能绘图、`pip check` 无依赖冲突。
2. **外部数据验收**：对指定数据源做一次低频小请求，记录查询日期、接口、标的和返回结果。

外部行情失败不应立即判定为环境失败。例如库能正常导入且 `pip check` 通过，但 Yahoo 返回 HTTP 429，说明失败发生在外部服务链路；此时不应连续重试。

## 数据接口的边界

| Python 接口 | 实际数据链路 | 当前用途 | 主要注意事项 |
|---|---|---|---|
| yfinance | Python → Yahoo Finance | 课程中的美股历史行情示例 | 非 Yahoo 官方 SDK；请求可能限流，接口行为会变化。 |
| AkShare `stock_us_daily` | Python → AkShare → 新浪财经美股接口 | Yahoo 不可用时的美股日线备用入口 | 与 Yahoo 的复权、字段、更新时间可能不同。 |
| AkShare `stock_zh_a_*` | Python → AkShare → 东方财富/新浪等 | A 股行情与基础数据 | 必须确认具体函数的数据源、频率、单位和复权方式。 |

“两个接口都返回 AAPL”不代表数据完全等价。实验必须记录数据来源、获取日期、市场、标的、时间区间、字段含义和复权口径，不能在同一回测中无说明地混用来源。

## 常见问题排查

| 现象 | 优先检查 | 处理方式 |
|---|---|---|
| `ModuleNotFoundError` | Notebook 的 `sys.executable` 是否指向 `pkm-quant` | 切换到 `Python (pkm-quant)`，不要先在系统 Python 重复安装。 |
| 终端与 Notebook 版本不同 | `python -V`、`which python`、内核路径 | 重新注册内核，并重启 Notebook 内核。 |
| `YFRateLimitError` / HTTP 429 | yfinance 版本、是否短时间重复请求 | 停止重试，稍后低频验证；必要时换用已注明来源的备用数据。 |
| `pip check` 报冲突 | 冲突包是否同时由 Conda 和 pip 管理 | 先修改 `environment.yml`，再统一同步；问题复杂时重建环境。 |
| 图表能运行但中文乱码 | Matplotlib 字体配置 | 在项目级绘图配置中指定可用中文字体，不改全局环境。 |
| 历史数据结果不一致 | 数据源、复权、时区和查询日期 | 固定数据快照并在实验报告中记录口径。 |

## 可复现实验清单

- 环境依赖写入 `environment.yml`，关键兼容版本明确固定。
- Notebook 明确使用 `Python (pkm-quant)` 内核。
- 实验报告记录 Python、主要库版本和运行日期。
- 数据报告记录来源、接口、获取日期、市场、标的、区间、频率、时区和复权。
- 数据清洗与接口兼容集中在 `实验/scripts/`，不要散落到每个 Notebook。
- 原始数据与处理后数据分开保存；正式比较优先使用可追溯的数据快照。
- 外部接口失败时保留错误类型，不把网络问题改写成策略或环境结论。
