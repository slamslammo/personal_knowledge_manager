# P2 工具栈要点（31–60 课）

P2 把 Python 工具在金融时间序列中的**数据语义、性能取舍和失效边界**讲清楚，而不是重复语法教学。整理产物：30 个逐课 Notebook + 6 个综合实验，全部在 `pkm-quant` 环境 `Restart Kernel and Run All` 通过，默认离线运行。

## 各模块核心结论

**环境与数值计算（31–33 课）**：可复现研究从环境固定和 manifest 记录开始。NumPy 广播天然适配「日期 × 资产」收益矩阵；矩阵运算支撑协方差与 PCA，但进入 NumPy 之前必须先由 Pandas 完成标签对齐——只比 shape 不比标签是隐蔽错误的主要来源。

**时间序列处理（34–39 课）**：DatetimeIndex 承载时区与交易日历语义；OHLCV 重采样只能降频聚合，不能上采样造信息。rolling 窗口与回撤计算要区分观察窗与决策时点；MultiIndex 分组支撑行业中性化；缺失值处理必须区分「停牌不可交易」与「数据缺失」（详见 [数据质量与清洗](node:c365data)）；财报与行情合并必须按 `available_at` 做时点一致连接（详见 [复权与数据对齐](node:c365adjust)）。

**数据与可视化（40–46 课）**：同一张结果表驱动全部图表，避免图与数不一致。yfinance / AkShare 只放在适配层，复权口径入库时显式记录；SQLite 行情库用幂等增量写入；完整数据流水线要能一键重建并输出 manifest。

**统计与模型（47–50 课）**：技术指标先写公式再谈时点可执行性；SciPy 拟合厚尾分布评估极端风险；statsmodels 因子回归配稳健标准误；sklearn 时序建模的核心是防泄漏——按时间切分、scaler 只在训练折拟合（详见 [未来函数与时点](node:c365lookahead)）。

**工程与性能（51–58 课）**：装饰器管理重试与缓存边界；asyncio 做受控并发获取；进程/线程并行有回测语义边界（不能跨期并行有状态回测）；Numba 加速数值循环但必须与原实现验算一致；pytest 固定量化计算的行为；Git 管实验版本，Docker 管环境版本。

**自动化交付（59–60 课）**：月报流水线幂等交付——同一输入重跑得到同一报告；阶段完成度用机器可读 manifest 审计。

## 贯穿 P2 的工程原则

1. **先透明、后封装**：首次出现的计算在 Notebook 展开，重复后才下沉到模块，不让封装遮蔽时间对齐、成本和未来信息。
2. **断言验证完整对象**：核对日期、证券顺序与数值，不只比行数和 shape。
3. **计算正确 ≠ 金融语义成立**：再平衡频率、信号/成交时点、年化常数、成本假设必须紧贴结果说明。
4. **默认离线**：教学数据用固定种子快照，真实接口只在适配层出现。
