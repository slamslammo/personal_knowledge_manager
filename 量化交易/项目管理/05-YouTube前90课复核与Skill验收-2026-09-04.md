## 403 根因与处理

1. 初次失败都使用 PAM 固定的 `yt-dlp 2026.07.04`；失败日志显示媒体 URL 返回 HTTP 403，并在连续请求后出现 HTTP 429。
2. 官方问题记录表明该版本后的 YouTube 兼容性修复已进入 `2026.08.19`。官方二进制 SHA-256 校验通过后，第 82、90 课无需任何凭据即可成功。
3. 第 30 课在新版默认客户端仍返回 403。按 yt-dlp 官方 PO Token 指南，临时隔离试用 `bgutil-ytdlp-pot-provider 1.3.2`，生成与该视频绑定的 mweb GVS PO Token 后成功。
4. 本轮未读取 YouTube 登录账号、浏览器 Cookie、API key 或 OAuth token，临时 PO Token 也没有写入项目文件。

因此，“以前能下载、现在个别课 403”不是工作区迁移或文件权限问题，而是 YouTube 对不同视频、客户端和媒体请求逐步执行 PO Token/反滥用策略，同时旧下载器存在兼容性回归。

## 工具链决策

- PAM 固定版已从 `yt-dlp 2026.07.04` 升级为 `2026.08.19`，旧版保留用于回滚。
- `bgutil-ytdlp-pot-provider 1.3.2` 已进入 PAM radar/review，但不常驻安装；仅在新版匿名路径仍失败的单个公开视频上作为受控回退。
- 默认不使用账号 Cookie。官方文档提示账号 Cookie 存在账号限流或封禁风险，而且公开内容通常不需要登录。
- 详细治理记录见 PAM：`reviews/2026-09-04-youtube-403-and-po-token-trial.md`。
