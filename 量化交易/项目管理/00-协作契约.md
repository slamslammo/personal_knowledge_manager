# 协作契约（Claude × Codex）

本文件约定量化板块双 Agent 分工的目录所有权、交接物和状态源。两个 Agent 通过本目录的管理文件协调，不依赖聊天记录传递状态。当前课程采集批次由 Claude 执行、Codex 只读验收；学习期间由 Codex 陪伴用户解惑并协助共建课程相关知识内容。工具能力说明以各自项目入口和 PAM Skill 为准，不能把能力归属等同于当前任务分工。

## 1. 分工总则

| Agent | 职责 | 不做什么 |
|---|---|---|
| 用户 | 先学习课程，再提出疑问、反例或发现的问题；确认自己的学习状态与持久化知识结论 | 不要求用户先把问题整理成正式笔记 |
| Codex | 当前 Claude 采集批次的只读验收；回答用户的课程疑问，结合课程素材和必要的一手资料核实；经用户确认后，共建 365 课程相关知识内容 | 未经任务板改派不写 Claude 正在处理的课程包；不把未核实的课程说法写成项目结论；持久化前先预览并请用户确认 |
| Claude | 当前指派课程批次的采集、转写、课件对照、摘要、HTML 与流水线登记；维护知识地图全局结构及非本次课程学习范围的内容 | 不替用户标记学习完成；不在 Codex 正与用户讨论的问题上先行定稿或覆盖未确认结论 |

## 2. 目录所有权

| 目录 | 所有者 | 另一方权限 |
|---|---|---|
| `pam-video-captures/365-days-quant-finance/` | 共享 | 均可写，但必须经 `_pipeline/lesson.py`；开工前在台账登记课号，避免并行冲突 |
| `量化交易/知识库/` 中由课程学习讨论产生的概念内容 | 用户与 Codex 共建 | 先由 Codex 给出拟写内容，经用户确认后再写；Claude 可审阅、补充，但不覆盖用户已确认的内容 |
| `量化交易/知识库/` 其余正文、TREE 结构、`build.py`、`知识地图.html` | Claude | Codex 可提出课程相关节点/结构建议；经用户确认并完成交接后再改全局结构 |
| `量化交易/365天量化课程.html` 与 PAM `knowledge-map.html` | PAM 源页由采集流程维护；PKM 镜像由同步脚本生成 | 不手工维护第二套逐课导航；需改导航源或同步逻辑时先登记并协调当前采集责任人 |
| `量化交易/实验/p1-*、p2-*` | Codex（生成流水线） | Claude 可引用报告链接，不改动 |
| `量化交易/项目管理/` | 共享 | 台账各改各的列（见下） |

## 3. 状态源与交接

- **`03-课程学习台账.md` 是课程层面的唯一状态源**：记录每课素材包是否通过、用户学习状态、课程整理/蒸馏状态。
- **`06-课程整理任务板.md` 是当前执行任务的唯一操作状态源**：记录任务领取、责任人、流水线阶段、验收与回执；不得用它覆盖或推断用户学习状态。任务通过验收后再回写课程台账。
- 学习问题由用户在学习时提出；Codex 对话中先解决理解与证据问题。只有经用户确认的稳定结论才进入课程相关知识节点；未决问题可暂留在对话中，或经用户同意后登记为待验证项，不混入采集验收状态。
- 课程台账中状态列的维护责任：
  - 「素材包」列：执行采集的一方更新（Codex 或 Claude，见目录所有权）；
  - 「学习」列：用户更新（或口头告知后由任一 Agent 代记）；
  - 「蒸馏」列：Claude 更新，完成时标注日期。
- 交接物约定：`_pipeline/lesson.py` 跑完第 1–7、9 步即视为素材就绪；第 8 步（对照课件复核 + 四段摘要）由执行方完成，未完成时流水线拒绝登记（退出码 4）。
- 蒸馏节奏：按**主题簇**（3–8 课）触发，不逐课蒸馏，也不等整个阶段学完。
- 课程整理统一走 `pam-video-captures/365-days-quant-finance/_pipeline/`，**规程只有一份：该目录 `README.md`**（含参数标定依据与回归要求，改动流水线后同步更新它）。九章自有体系的正文需与用户讨论后才写入。365 课程导航继续按官方课号以 PAM 页面为唯一入口；概念解释和学习所得沉淀在量化知识节点，不另造逐课导航。
- 当前 P5（131–160）指派以任务板为准：Claude 执行课程采集整理，Codex 负责只读进度核查与验收；未由用户改派前，Codex 不得并行处理该区间。
- `pam-video-captures/` 无 Git 且流水线会更新共享索引时，必须串行：一次只运行一个课程任务；执行方每课写完回执后再领取下一课。并行安全尚未建立前，不以批量目录生成代替逐课验收。

## 4. 已知约束（双方都不得破坏）

1. 两项目必须保持兄弟目录：工作区根目录下并列放置 `personal_knowledge_manager/` 与 `pam-video-captures/`。课程 `knowledge-map.html` 使用相对链接指向 PKM 实验报告；PKM 知识地图通过同步页反向进入课程页面。**任何一方移动目录前先通知用户。**
2. `pam-video-captures/` 目前无 git；`量化交易/` 已于 2026-08-04 纳入 PKM 仓库跟踪（实验报告 HTML 走 gitignore，可由 notebook 重新导出）。采集侧仍无版本控制，破坏性操作前先备份。
3. 2026-09-04 已完成迁移收口：Codex 维护的课程采集脚本、P1/P2 生成器和入口链接统一从脚本位置推导目录或使用跨兄弟项目的相对路径。后续不得重新加入工作区绝对路径；运行输出也不应把绝对工作目录固化为长期状态源。

## 5. 冲突规则

- 需要跨界修改时，先在台账「备注」列留言，由用户仲裁后执行。
- 节点 id（`<!--# id -->`）一经建立不得更改，双方引用均以 id 为准。
- 本契约修改需用户确认；本轮用户已明确授权补充 Codex 的课程学习陪伴与知识共建职责。两个入口文件（`AGENTS.md`、`CLAUDE.md`）只做指针，不写规则正文。
