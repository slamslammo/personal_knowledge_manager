# 协作契约（Claude × Codex）

本文件约定量化板块双 Agent 分工的目录所有权、交接物和状态源。两个 Agent 通过本目录的管理文件协调，不依赖聊天记录传递状态。对应 personal_agent_manager 中的能力划分：Codex 执行 `source-capture-video`，Claude 执行 `pkm-writing` 与 `html-knowledge-map`。

## 1. 分工总则

| Agent | 职责 | 不做什么 |
|---|---|---|
| Codex | 课程采集、逐课素材包（视频/字幕/截图/summary/index.html）、notebook 流水线与验收 | 不写知识库正文，不改 PKM 节点结构 |
| Claude | 知识蒸馏：把主题簇沉淀为知识库节点正文、维护 TREE 与课程映射、重建知识地图 | 不改课程素材包，不动采集流水线 |

## 2. 目录所有权

| 目录 | 所有者 | 另一方权限 |
|---|---|---|
| `pam-video-captures/365-days-quant-finance/` | Codex | 只读（Claude 读 summary.md、timeline、大纲审计作为蒸馏原料） |
| `量化交易/知识库/`（资料层含两门课程轨、体系层九章）、`build.py`、`知识地图.html` | Claude | 只读 |
| `量化交易/实验/p1-*、p2-*` | Codex（生成流水线） | Claude 可引用报告链接，不改动 |
| `量化交易/项目管理/` | 共享 | 台账各改各的列（见下） |

## 3. 状态源与交接

- **`03-课程学习台账.md` 是唯一状态源**。一课一行，三个状态列分别由三方维护：
  - 「素材包」列：Codex 更新；
  - 「学习」列：用户更新（或口头告知后由任一 Agent 代记）；
  - 「蒸馏」列：Claude 更新，完成时标注日期。
- 交接物约定：Codex 每课交付 `summary.md`（主线/关键概念/方法边界/价值四段结构）即视为素材就绪；Claude 蒸馏只依赖 summary 与 index.html，不要求重看视频。
- 蒸馏节奏：按**主题簇**（3–8 课）触发，不逐课蒸馏，也不等整个阶段学完。
- 蒸馏产物落在**课程轨**（`知识库/01-资料清单/` 下的课程子目录）；九章自有体系的正文另行与用户讨论后才写入，不由蒸馏直接填充。

## 4. 已知约束（双方都不得破坏）

1. 两项目必须保持兄弟目录：`_暂存/personal_knowledge_manager/` 与 `_暂存/pam-video-captures/`。课程 knowledge-map.html 有 141 条相对链接指向 PKM 实验报告；PKM 知识地图有反向链接指向课程页面。**任何一方移动目录前先通知用户。**
2. `pam-video-captures/` 目前无 git；`量化交易/` 已于 2026-08-04 纳入 PKM 仓库跟踪（实验报告 HTML 走 gitignore，可由 notebook 重新导出）。采集侧仍无版本控制，破坏性操作前先备份。
3. Codex 的 builder 脚本内有绝对路径（`COURSE_ROOT` 等约 300 处），换机器或改目录会失效，暂不修复但不再新增。

## 5. 冲突规则

- 需要跨界修改时，先在台账「备注」列留言，由用户仲裁后执行。
- 节点 id（`<!--# id -->`）一经建立不得更改，双方引用均以 id 为准。
- 本契约修改需用户确认；两个入口文件（`AGENTS.md`、`CLAUDE.md`）只做指针，不写规则正文。
