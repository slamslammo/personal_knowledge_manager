### 1.2 四个结构性缺口

**缺口 1：采集严重超前于消化。** 素材已到 160 课，用户实际学到第 64 课，知识蒸馏停在第 66 课。67–160 课共 94 课素材已采集但未被学习——继续采集的边际收益极低。

**缺口 2：所有实验跑在合成数据上。** 实验数据全部标注 `identity: synthetic`，标的命名为 `SIM_MARKET` / `SIM_VALUE` / `SIM_GROWTH`，种子 365。这意味着**已学完的数据工程知识从未在真实 A 股数据上验证过**——真实数据的复权错位、停牌缺失、ST 摘帽、财报披露时点这些坑，合成数据一个都不会出现。这是当前最实质的缺陷。

**缺口 3：三个核心领域是空的。** 因子与多因子（82–89 课已讲完但零沉淀）、回测引擎（全库没有自己写的完整引擎）、风险管理与组合构建——九章体系 38 个节点绝大多数是 400–600 字节的概念占位符。

**缺口 4：没有任何用户本人的持仓记录。** 全库检索 `持仓/自选股/实盘/我的账户/券商账户` 等关键词，命中项全部是课程讲师的教学举例（老纪、老康等虚构人物），无一条是用户真实数据。

## 二、三个维度的定位与关系

三个维度不是并列的三份工作，而是一个闭环的三段：

```text
   维度 3  实盘/自选跟踪  ──产生真实问题──▶  维度 1 知识体系
        ▲                                        │
        │                                        │ 决定要学什么
        │                                        ▼
        └────── 用真实数据验证 ────────  维度 2 工具平台
                 （选什么工具取决于要回答什么问题）
```

| 维度 | 定位 | 输入 | 产出 | 当前状态 |
|---|---|---|---|---|
| 1. 量化知识 | **内容层**：把课程素材转化为自己的体系 | 67–160 课待消化素材 | 九章体系正文、成文节点 | 停在 66 课，九章多为占位符 |
| 2. 工具平台 | **手段层**：选什么工具回答什么问题 | 开源生态实况 | 可落地的工具链 + 验收结论 | 有清单，部分判断已过时 |
| 3. 实盘跟踪 | **反馈层**：真实账户产生真问题 | 用户持仓/自选 + 每日行情 | 每日复盘、持仓诊断 | **完全空白** |

**核心判断：当前应以维度 3 为锚，倒推 1 和 2。**

理由是三条线现在互相脱节：学到的知识用合成数据、工具清单没有 A 股链路、实盘完全空白。一旦有了真实持仓，就有了真实问题（"我的持仓为什么跌""这个因子在 A 股有效吗"），这些问题会自动决定该学什么、该用什么工具。这比"先学完 160 课再动手"的路径要短得多，也更容易坚持。

反过来，如果先补齐维度 1 和 2，学到的东西仍然无处落地，很容易重复过去"采集超前、消化滞后"的模式。

### 3.4 四条关键判读

**判读 1：回测层存在范式裂缝，两者是串行互补而非竞争关系。**

| 范式 | 代表 | 优势 | 代价 |
|---|---|---|---|
| 向量化 | vectorbt、backtesting.py | 速度快 100 倍级，适合大规模参数扫描 | 成交逻辑简化，与实盘有偏差 |
| 事件驱动 | RQAlpha、LEAN、NautilusTrader、vn.py | 逐笔/逐 bar 仿真，执行逻辑真实 | 慢，参数扫描成本高 |

正确用法是**先用向量化筛掉海量假设，再用事件驱动验证幸存者的执行真实性**。把两者对立选择是常见的架构失误。这条对项目现有"pandas → RQAlpha/Qlib → 完整系统"的选型顺序是有效补充——它解释了为什么需要两级，而不只是说"先简单后复杂"。

**判读 2：两个最"推荐"的入门框架已经死了，但 Star 数仍在误导新手。**

backtrader 23.5k star、zipline 20.1k star，网上教程仍大量引用，但均已停止维护。zipline 的活体继承者是 `zipline-reloaded`（约 1.9k star，2026-01 仍在更新），但它以美股 bundle 为中心。同类已停更的还有 blankly（2024-12）、QSTrader（2024-06，休眠）。

同批停更的还有 **alphalens**（因子检验工具，2024-02-12，与 zipline 同期）——Quantopian 关停后的两个产物都已无人维护，因子检验这一环目前没有公认的活跃工具。**zipline-reloaded 是唯一活着的继承者**（1,974 star，2026-10-25 仍在推送），但它以美股 bundle 为中心。

> 对本项目的影响：项目现有清单提到"backtrader/vnpy/zipline/freqtrade 从未实际使用"，但**未标注这几个项目已停止维护**。这是清单里最该补的一条——它直接决定了"值不值得花时间去学"。

**判读 3：AI 量化工作台是 2025 年后的新物种，QuantDinger 是当下增长最快的，但它没有 A 股通道。**

QuantDinger 2025-12-28 创建，10 个月涨到 13.1k star，v5.5.1，Apache-2.0，主打 Docker 自托管 + 数据主权 + 多 LLM 集成（9 种）+ 58 个 MCP 工具，技术栈为 FastAPI + Celery + React + DuckDB。

必须记录的边界：
- **实盘场所为 CCXT 交易所 + IBKR + MT5，均不含 A 股。**
- 存在未关闭的实质 Bug：#177（MDD 指标可能不正确）、#171（AI 流程部分未打通）、#178（组合策略执行时间问题）。
- 项目年轻，A 股实盘链路、撮合真实性、风险隔离均需独立验收。

> 对本项目的影响：现有清单对它的判断停留在"项目很新、功能面很宽，需独立验收"。这条判断**方向正确但已需更新数据**——它现在不是"很新"的 Demo，而是有 13k star 和 v5.5.1 生产形态的项目，但"A 股无通道"这条硬约束使得它对本项目的直接价值有限。

**判读 4：清单遗漏了一个 A 股原生的活跃选项——Hikyuu。**

Hikyuu 是国产 C++/Python 量化框架（Apache-2.0，3,579 star，2026-10-26 当日仍在推送，近 30 天 +57 star），深度适配 A 股，但在本项目现有清单中**完全没有提及**。它的定位与主流框架都不同：

- **性能**：官方实测 AMD 7950x 上，A 股全市场 1,913 万条日 K 线，计算 20 日均线在预热后约 166ms。
- **组件化**：把系统化交易拆成市场环境判断、系统有效条件、信号指示器、止损止盈、资金管理、盈利目标、滑点、多因子、资金分配等独立组件，可分别建库、自由组合。
- **存储**：HDF5 / MySQL / ClickHouse / SQLite 四种后端，默认 HDF5。
- **边界**：README 明确声明是个人学习与学术研究工具，不提供投资建议或直接交易服务；多市场与实盘接口支持弱。

> 它与 QuantDinger 形成一组对照：**QuantDinger 功能最全但没有 A 股通道，Hikyuu 最贴近 A 股但没有实盘链路**。两者都不能单独满足本项目需求，这印证了下节的结论。

### 3.5 对 A 股实操者的硬约束（本次分析最重要的结论）

**主流开源量化平台几乎都不原生支持 A 股。**

| 项目 | A 股支持情况 |
|---|---|
| QuantDinger | 实盘 8 场所为 CCXT/IBKR/MT5，**无 A 股** |
| LEAN | 多资产但美股优先，本地引擎开源不代表数据免费 |
| NautilusTrader | 无 A 股券商适配（社区文档明确记录其无印度券商/NSE，A 股同理） |
| vn.py | **有**，但主要是 CTP 期货接口；股票通道依赖券商/操作系统/账户条件 |
| Qlib | 有 A 股数据，但只是研究平台，**不做实盘下单** |
| freqtrade | 仅加密货币 |

结论：**A 股链路必须自建**。取数走 AKShare / baostock，回测自建或选 Qlib，实盘环节依赖券商条件。那种"装一个平台就打通研究到实盘"的期待，在 A 股场景下不成立。

数据源侧同样如此，免费方案的稳定性梯度清楚：

| 数据源 | 定位 | 硬约束 |
|---|---|---|
| **AKShare** | 主力，覆盖最广 | 本质是爬虫聚合，源站改版即失效；频繁使用易封 IP；延迟约 500ms，**不适用高频 tick** |
| **baostock** | 日线/财报历史，稳定性高 | 无实时行情、无盘口，不支持分钟级 |
| **efinance** | 轻量替代（东财单源） | 数据源单一，维护不够活跃 |
| **Tushare Pro** | 财务因子、结构化历史 | 积分制，部分接口需高等级权限 |
| 新浪/东财直连 | 快速验证 | 非官方接口，无服务保障 |

社区共识方案是 **AKShare 主力 + 东财接口补实时 + Tushare 做交叉校验**，且必须加缓存、字段校验、异常告警。理由很实际：某天某只股票成交量两源差 10 倍，通常是复权处理不一致导致的，单源发现不了。

### A 股实盘自动化只有三条路径，门槛差异极大

| 路径 | 优点 | 约束 | 适用 |
|---|---|---|---|
| **券商官方程序化接口**（QMT、PTrade、中泰 XTP、华泰 MATIC、东财 EMC） | 合规、稳定、低延迟 | **资金门槛高**，部分券商 QMT / PTrade 要求数百万元资产，需单独开通权限 | 满足门槛的投资者 |
| **第三方量化平台**（聚宽、BigQuant 等） | 合规、上手快、数据与回测一体 | 有服务费，策略自由度受平台限制，且**策略代码留在云端** | 新手入门 |
| **模拟券商客户端操作**（easytrader） | 几乎零成本 | **灰色地带**：可能违反券商用户协议；明文密码；券商软件一更新即失效；**仅支持 Windows** | 能承受风险的开发者 |

监管背景需记录：证监会对程序化交易有报告义务与异常交易监控要求（高频申报、频繁撤单、拉抬打压等受重点监控），内外资一致。

> **对维度 3 的直接结论**：用户当前环境为 macOS，**easytrader 路径直接排除**。若券商账户未达 QMT / PTrade 门槛，则个人条件下 A 股自动下单链路基本不成立。这时维度 3 的现实形态不是"自动交易"，而是**本地计算信号 + 人工下单 + 系统化跟踪复盘**。这一点必须在规划阶段就定死，否则会设计出做不出来的方案。

### 3.6 初步候选路径

结合项目当前状态（学到 64 课、无真实数据、无持仓），候选路径按阶段排列：

| 阶段 | 动作 | 依赖 |
|---|---|---|
| 近期 | 用 **AKShare 建本地 A 股日线库**，把 P1/P2 实验在真实数据上重跑一遍 | 需要用户给出关注的标的范围 |
| 近期 | 回测用 **pandas 最小回测 + backtesting.py**（AGPL-3.0，约 20 行跑通，仅单品种）保持透明 | 无 |
| 中期 | 因子阶段用 **Qlib**（A 股数据友好，MIT）；因子检验目前**无公认活跃工具**（alphalens 已停更），需自建或用 Qlib 自带能力 | 学到 82–89 课 |
