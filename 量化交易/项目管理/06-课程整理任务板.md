### 角色与并行边界

- 用户：确定目标范围，处理身份冲突、来源例外和内容取舍等灰区；课程学习状态只由用户确认。
- Claude：本批 131–160 的唯一内容执行者；按课程逐条推进，每课结束后更新本板的执行状态、阶段和回执。只改当前任务范围内的素材包及流水线登记副产物。
- Codex（本批）：只读检查素材、验收记录和课程索引；通过或退回时更新“Codex验收”列。未经用户另行安排，不下载、不重跑流水线、不改课内摘要或字幕。
- Codex（学习支持，独立于本批验收）：用户先看课程，再带来疑问或发现的问题；Codex 结合对应课程素材解释、核实、举例，必要时提出最小实验。稳定结论须先让用户确认，再沉淀到 `知识库/` 的相关概念节点；新增节点或改地图结构先给预览并协调 Claude。此职责不改变 Claude 对 131–160 素材包的执行权，也不把讨论中的观点写成采集验收结果。
- `pam-video-captures/` 没有 Git 版本控制，且流水线会写共享索引；因此本批**串行处理，一次只允许一课处于实际写入中**。不要启动并行子任务或让两个 Agent 同时运行 `lesson.py`。
- 课程包的 `package_status: draft` 是预期状态：它表示尚未逐句人工听校，不等于采集失败。采集任务可在素材结构验收通过后完成，但必须保留这一质量边界。

### 单课验收

每课对照 `_pipeline/README.md` 及包内记录逐项验收：

1. 课号、标题、来源视频 ID 相互吻合；口播课号冲突时停止登记，未自报时须如实标注并补充身份依据。
2. 有本地完整媒体；分辨率、实际时长与全片解码结果可核对，访问方式如实记录，不使用未授权 Cookie 或账号凭据。
3. Whisper 原始稿、校订稿和审计记录齐全；时间线字幕分配无遗漏、无重复，课件截图与口播段对应可查。
4. `summary.md` 的四个部分有实质内容和对应证据锚点，无 `PAM_TODO`；摘要正文不能只靠“文件存在”判通过。
5. 本地 `index.html` 可用相对路径打开；`acceptance.json`、`capture_attempt.md`、`series.json` 的状态与实际文件一致，没有“摘要已完成却仍记为缺摘要”等互相矛盾的记录。
6. 采集结构验收通过后，索引登记完整；仍未逐句人工听校的包继续标 `draft` 并明确注明。
