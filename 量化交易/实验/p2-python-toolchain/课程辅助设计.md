# P2 课程辅助设计

## 目标

把第 31–60 课从「视频和图文口播」转化为可运行、可验证、可继续工程化的量化学习实验。重点不是重复 Python 语法，而是说明同一个 Python 工具在金融时间序列中的数据语义、性能取舍和失效边界。

## 稳定设计决策

1. **课程大纲是主键**：每课一个 Notebook，文件名保留课程编号；不以自定义分类替代官方大纲。
2. **逐课学习 + 模块综合**：30 个逐课 Notebook 负责单节知识，6 个综合实验负责研究闭环。
3. **统一环境**：沿用 Datawhale 课程建立的 `pkm-quant`；阶段依赖进入同一 `environment.yml`，只有发生真实冲突时才拆分扩展环境。
4. **默认离线**：数据接口与研究计算分离。教学 Notebook 默认读取带来源说明的数据快照，避免限流和接口变更破坏复现。
5. **先透明、后封装**：第一次出现的计算在 Notebook 展开；跨课重复后再下沉到 `src/`，不让框架遮蔽时间对齐、成本和未来信息。
6. **正确性优先于速度**：性能实验必须有小样本基准、形状/索引断言和结果一致性检查。
7. **量化边界显式化**：每个 Notebook 至少说明时间口径、标签对齐、缺失值、未来函数、成本或样本外边界中与本课相关的部分。
8. **目的先于代码**：非平凡代码前先说明要解决的量化问题、输入、输出和使用场景；避免用紧凑语法遮蔽核心概念，首次实现优先采用可逐步阅读的写法。
9. **数据来源先行**：Notebook 页首明确标注真实、模拟或脱敏数据，并记录标的、时间、频率、复权、时区和生成方式中适用的字段；模拟数据不得使用会被误认为真实证券的名称。
10. **解释贴近结果**：Markdown 负责方法参数、shape/axis、量化意义和边界；代码块顶部用一句话说明本块目的，仅在切片、关键轴和确定性小数组旁保留简短行尾结果。一个代码块只承载一个核心概念，输出优先使用带标签表格或可核对的确定值。
11. **先小例子、后完整行情**：矩阵乘法、窗口、时区、风险和优化等不易直接核对的概念，先用能手算的确定性小例子说明，再回到完整行情；小例子负责解释语义，完整数据负责验证量化场景。
12. **断言验证完整对象**：不能只比较行数或 shape。涉及标签选择、Pandas/NumPy 转换和两种实现对照时，同时核对日期、证券顺序与数值；进入 NumPy 前先由 Pandas 完成标签对齐。
13. **计算与交易假设分开**：代码正确不等于金融语义成立。固定目标权重、再平衡频率、信号生成/成交时点、年化、缺失样本和成本假设必须紧贴结果说明。
14. **图表必须自解释**：标题、坐标轴、图例和单位要能独立说明图中对象；信号发现日与成交日不得混称。静态图需检查中文字体和导出清晰度，交互图需同时验证离线 HTML 文件与静态课程报告中的入口。
15. **入口服从课程大纲**：PAM 的 `knowledge-map.html` 是唯一课程入口；大纲中的逐课链接进入对应静态报告。M1–M6 的模块说明与 L1–L6 综合实验合并成同一个模块头区块，已完成实验提供报告与 Notebook，未完成实验只显示开发状态。本项目只生成 Notebook、报告和实验产物，不再生成独立课程首页。

## 每个 Notebook 的标准结构

1. 课程定位与来源。
2. 本节量化问题。
3. 代码目标、输入与预期输出。
4. 课程代码示例的可运行复现。
5. 对应的行情或组合场景。
6. 易错实现与失败示例。
7. 稳健实现、断言和性能比较。
8. 方法边界。
9. 可复用结论和练习。

其中第 4–7 步优先采用统一呈现单元：

> 方法与参数说明 → 单一概念代码块 → 带标签或确定值输出 → 量化意义与边界

## 环境策略

当前统一环境：`pkm-quant`，Python 3.11。第 31–42 课使用 NumPy、pandas、Matplotlib、SciPy、scikit-learn、Jupyter、nbclient、Plotly 与 mplfinance；第 43–60 课继续在同一环境使用 statsmodels、Numba、pytest、Jinja2，以及 Python 标准库中的 sqlite3、asyncio、concurrent.futures、contextlib 和 subprocess，不另建课程专用环境。

后续 P2 预计补充：

- 已写入主环境：Plotly、mplfinance、statsmodels、Numba、pytest。
- 后续只有形成稳定工作流后再考虑：ipdb、Jupytext。
- 验证后决定：TA-Lib（涉及 macOS ARM 原生依赖）。
- 不进入 Conda：Git、Docker。
- 无须安装：asyncio、multiprocessing、sqlite3、contextlib。

## 数据策略

当前第 31–42 课提供两份固定随机种子的基础合成数据，并在逐课 Notebook 中构造可手算的小样例和业务状态：

- 多资产日线：演示收益矩阵、协方差、PCA、标签对齐、rolling 和回撤。
- A 股交易时段 5 分钟线：演示 DatetimeIndex、时区、OHLCV 和 VWAP 重采样。
- 缺失、停牌与上市状态：分别保留原始价格、估值价格、缺失原因和 `tradable`，不把填充值当作成交价。
- 行业与财报样例：演示逐日行业截面、资金暴露以及按 `available_at` 做 point-in-time 对齐。

教学数据保留市场结构特征，但不冒充真实行情。后续增加真实数据时，必须记录来源、获取日期、复权、时区、频率、字段和数据版本。

## 验收

- `Restart Kernel and Run All` 通过。
- 默认离线运行。
- 内核为 `Python (pkm-quant)`。
- 无隐藏执行顺序依赖。
- 关键数组形状、索引唯一性、时区和结果一致性有断言。
- 图表输出进入 `outputs/`。
- Notebook 输出不保留未解释的 Warning/Traceback；教学性失败示例必须捕获异常并说明原因。
- 静态 HTML 不引用缺失的本地资源；独立图片要有可读标题、图例、坐标轴和单位。
- PAM 知识地图中的逐课代码实践链接和模块综合实验入口指向当前产物；本项目内不保留第二套独立首页。
- 方法说明能追溯到课程编号和对应图文口播。
- 机器整理不替代课程原始材料；公式、数字和代码以可运行验证结果为准。

## 迭代规则

- 每批开始前在 `迭代记录.md` 写范围和设计变化。
- 每批结束后记录执行结果、环境变更、未解决问题。
- 改动稳定设计决策时，先更新本文件，再批量修改 Notebook。
- 不仅提交结果 Notebook，也保留生成和批量验收工具。
