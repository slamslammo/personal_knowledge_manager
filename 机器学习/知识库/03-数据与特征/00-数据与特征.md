# 数据与特征

模型不会直接理解现实对象，只会接收整理后的数值表示。进入算法之前，必须先回答：一行数据代表什么、哪些信息是输入、要预测什么、输入是否可靠，以及怎样把原始记录转换成模型能够稳定使用的特征。

这也是本章放在模型评估和具体模型之前的原因。任务与输入尚未定义清楚，后面的损失、训练和指标就没有可靠基础。

## 四类工作

| 工作 | 回答的问题 | 典型内容 | 最终产物 |
|---|---|---|---|
| 数据定义 | 学习对象和目标是什么 | 样本、特征、标签、分类、回归、聚类、降维 | 明确的 $X$、$y$ 与任务 |
| 数据诊断 | 数据当前有什么问题 | 分布、缺失、异常、重复、类别比例、变量关系 | 数据质量判断 |
| 数据预处理 | 如何形成稳定一致的输入 | 划分、填补、编码、缩放、异常处理 | 可复现的转换流程 |
| 特征工程 | 怎样改善模型看到的表达 | 选择、构造、组合、变换、压缩 | 更适合任务的特征表示 |

数据诊断负责发现问题；预处理和特征工程负责采取行动。三者经常连续发生，但不能混为一谈。例如，相关性热力图是诊断工具；根据相关性删除重复特征才是特征选择。

## 一条完整主线

`原始记录 → 定义样本与目标 → 诊断数据 → 划分数据 → 预处理 → 特征工程 → 模型输入`

其中有两条贯穿原则：

- **预测时可获得**：训练使用的每个特征，在真实预测发生时都必须能够取得。
- **只从训练集学习**：均值、方差、类别集合、填补值和被选特征都只能从训练集估计，不能提前查看验证集或测试集。

第二条原则把本章和后续 [数据泄漏](node:leakage)、[Pipeline 与 GridSearchCV](node:pipeline) 直接连接起来。

## Iris 如何承担共同例子

Iris 鸢尾花有 150 个样本、4 个连续数值特征和 3 个均衡类别，适合验证从数据理解到分类建模的基础流程。

| 本章问题 | Iris 中的验证 | 实验输出 |
|---|---|---|
| 数据结构是否清楚 | 一行是一朵花，四列测量值构成输入，品种是标签 | 数据概览与类别分布 |
| 特征是否具有区分力 | 比较四个特征在三个类别中的分布 | 分组分布图 |
| 是否需要缩放 | 原始特征范围不同，标准化后变成可比较尺度 | 缩放前后对比 |
| 特征是否重复表达信息 | 花瓣长度和花瓣宽度高度相关 | 相关性图与二维散点图 |
| 能否构造新表达 | 用花瓣长度与宽度构造面积代理特征 | 构造特征分布图 |

Iris 本身没有缺失值，也没有作为输入的类别型特征，因此它不能诚实覆盖缺失值填补和 one-hot 编码。本章讲清这些方法的适用条件；后续遇到混合类型数据时再做对应实验，不为凑齐流程而伪造结论。

传统机器学习通常更依赖人工理解和设计特征；深度学习更强调从数据中自动学习表示。但数据定义、划分、质量检查、泄漏防范和可复现转换，在两类方法中同样成立。
