# 部署指南

> 本文说明如何验收 AI 资讯任务，并把它部署到一个或多个定时运行平台。部署所需的参数集中在 `config/task.yaml` 和 `config/runtime.yaml`，本文按平台说明怎么配置。

## 1. 设计原则

- **入口提示词**（`prompts/routine-prompt.md`）是贴进定时任务的唯一内容，只放四类东西：引导去读执行手册、授权范围、安全边界、失败通知。它不写具体步骤，也不写平台专属的工具名，所以换平台、改流程都不用改它。
- **执行手册、模板、配置、脚本**只写平台无关的步骤：shell、git、python3、联网搜索，加上"用所在平台的通知方式"这类说法。
- **平台相关的做法**（定时、通知、沙箱与网络）只写在本文第 4 节。
- **不预设平台的先后**：可以部署在多个平台上，各平台贴同一份入口提示词，由协调锁决定谁运行、谁校验（`方案.md` 7.9 节）。只部署一个平台时，它独立完成全部工作。
- `scripts/check_portability.py` 检查以上约定：执行文件里不能出现平台专属的写法，执行手册不能让智能体直接做 git 写操作，入口提示词不能引用手册的步骤编号。它随单元测试自动运行。

## 2. 部署前提

| 能力 | 用途 | 必需 |
| --- | --- | --- |
| 定时触发 | 主平台每周一 10:00（Asia/Shanghai）；第二个平台建议错开 1 小时以上 | 是 |
| Shell、git | 执行脚本；`coord.py` 提交推送 | 是 |
| python3（带 PyYAML） | 运行 `scripts/` 下的协调、采集、排名、校验脚本 | 是 |
| 命令可以联网 | 脚本访问 Trendshift、OSS Insight、HN、Hugging Face；git 推送 | 是 |
| 命令可以访问任意网站 | `fetch_articles.py` 读取 HN 高分帖链接的原文 | 否：做不到时原文读取失败并降级，不影响其他采集 |
| 联网搜索 | 官方发布、媒体报道、传播分析 | 是 |
| 推送本仓库 `main` 的凭证 | 协调锁、周报、数据和状态文件都推送到 `main`；推送不了就无法运行 | 是 |
| 发送通知 | 把周报精简版推送给用户；没有时把通知作为运行的最后输出，由调度方转发 | 否 |

模型选择平台上的高档通用模型，思考强度设为最高。仓库文件中不写具体型号，在平台设置中选择。

## 3. 部署前验收（开发会话）

开发会话是测试环境，定时任务是运行环境。任务工程有改动时，先在开发会话里完整跑一遍，产出确认符合预期后再部署：

1. 运行单元测试：`python3 -m unittest discover -s AI资讯/任务/scripts/tests -t AI资讯/任务/scripts/tests`。其中包括可移植性检查，以及用本地裸仓库模拟多个智能体并发抢锁的集成测试（约半分钟）。
2. 按入口提示词和执行手册运行一次，参数加 `TEST_RUN=1`；要测指定的周，再加 `TARGET_WEEK=YYYY-Www`。测试模式下 `coord.py start --test` 把远端换成本地模拟仓库：锁、提交、推送完整走一遍，不碰 GitHub、不改本地分支和工作区，也不发通知；通知内容在最后输出。
3. 审阅产出（`/tmp/ai-weekly/out/` 下的周报和数据文件）、执行记录（`trace_view.py --local`）和通知内容，按反馈调整规则后重跑。
4. 走 PR，等审查结束后合并；然后按第 4 节部署或更新定时任务。

定时任务的会话只用于运行和诊断。要改任务工程，回到开发会话走 PR，不在定时任务里直接改。

## 4. 平台适配

### 4.1 能力对应

| 能力 | Claude Code 云端定时任务 | Codex | 自建调度（cron 或 CI + 任意智能体 CLI） |
| --- | --- | --- | --- |
| 定时 | 定时任务设置周一 10:00（GMT+8） | Codex 应用的自动化任务；或 cron / GitHub Actions 调用 `codex exec` | `CRON_TZ=Asia/Shanghai` 下的 `0 10 * * 1`，或 UTC 的 `0 2 * * 1` |
| 运行入口提示词 | 定时任务的提示词框 | `codex exec`，提示词从标准输入读取 | 智能体 CLI 的非交互模式 |
| `--platform` 取值 | `claude` | `codex` | 该智能体的小写名称 |
| 联网搜索 | 内置 | 加 `--search`（实时搜索；不加时用缓存索引） | 平台内置搜索或搜索 API |
| 命令联网 | 环境网络设为"完全访问" | 沙箱默认不联网：`-s workspace-write -c sandbox_workspace_write.network_access=true` | 运行环境放行第 2 节列出的站点 |
| 推送凭证 | 定时任务挂载本仓库后由平台注入；2026-10-29 实测可直接推送 `main` | 运行环境里的 git 凭证 | 只对本仓库有内容写权限的细粒度 token 或部署密钥 |
| 通知 | PushNotification，内容放在 `<routine_summary>` 标签里，首句作为横幅 | 没有内置推送：用 `-o <文件>` 保存最后一条消息，由调度脚本转发 | 由调度脚本转发最后输出（邮件、IM 机器人等，待定，见版本规划"多渠道每周通知"） |

### 4.2 Claude Code 云端定时任务（主平台）

1. **环境**：定时任务使用的云端环境，网络访问设为"完全访问"。环境可能被多个会话共用，修改会影响所有使用它的任务。
2. **GitHub 授权**：在"连接器 → GitHub 集成"中连接 GitHub 账户并安装 Claude GitHub 应用；在定时任务的编辑页把本仓库加入仓库列表。仓库在会话启动时挂载，运行中不会补加。
3. **定时任务配置**：

| 项目 | 设置 |
| --- | --- |
| 运行时间 | 每周一 10:00，时区 GMT+8 |
| 模型 | 高档通用模型，思考强度最高 |
| 仓库 | slamslammo/personal_knowledge_manager |
| 提示词 | 复制 `prompts/routine-prompt.md` 全文 |

执行手册、脚本和配置合并到 `main` 后，下一次运行即生效；只有 `routine-prompt.md` 本身变化时才需要重新粘贴。

### 4.3 Codex（第二个平台）

部署方式待定（`方案.md` 第 12 节）。以下命令按 Codex CLI 0.165 的 `codex exec --help` 核对过；GitHub Actions 与 Codex 应用的自动化任务以 OpenAI 官方文档为准，本项目尚未实测。

**方式 A：cron 加 `codex exec`（本机或服务器）**

1. 准备一个**专用的**仓库克隆（不要用日常编辑的那份），配置只对本仓库有写权限的 git 凭证，登录 Codex CLI，安装 python3 与 PyYAML。
2. 测试模式先跑一次（在仓库根目录）。测试模式不改本地分支和工作区，不碰 GitHub：

   ```bash
   { echo "TEST_RUN=1"; echo; cat AI资讯/任务/prompts/routine-prompt.md; } \
     | codex exec --search -s workspace-write \
         -c sandbox_workspace_write.network_access=true \
         -o /tmp/ai-weekly-last.txt -
   ```

3. 正式运行时去掉第一行的 `TEST_RUN=1`，放进 crontab，时间比主平台晚 1 小时以上：

   ```bash
   CRON_TZ=Asia/Shanghai
   0 11 * * 1  cd /path/to/personal_knowledge_manager && codex exec --search -s workspace-write -c sandbox_workspace_write.network_access=true -o /tmp/ai-weekly-last.txt - < AI资讯/任务/prompts/routine-prompt.md
   ```

4. 通知：Codex 没有推送到手机的功能，`/tmp/ai-weekly-last.txt` 里是最后一条消息（含通知内容），由 cron 脚本转发，转发渠道待"多渠道每周通知"确定。主平台已完成、它只做了校验或直接退出时，最后输出里没有周报通知。

**方式 B：GitHub Actions**：用 `on: schedule`（cron `0 3 * * 1`，即北京时间周一 11:00）触发 `openai/codex-action@v1`，提示词用 `routine-prompt.md` 全文。需要仓库 secret `OPENAI_API_KEY`，任务的 `permissions` 要有 `contents: write` 才能推送 `main`。

**方式 C：Codex 应用的自动化任务**：按官方文档设置每周一 11:00 运行，提示词贴 `routine-prompt.md` 全文，并确认运行环境允许命令联网和推送。

### 4.4 跨平台验收清单

新平台首次部署时逐项检查，结果记入 `版本规划.md`：

- [ ] 测试模式（`TEST_RUN=1`）跑通：`check_run.py` 通过，`coord.py publish` 推送到模拟仓库，通知内容出现在最后输出里。
- [ ] 正式运行一次：周报、数据文件和状态文件进入 `main`，`git log` 里的提交信息为"AI 周报 {WEEK}"和"AI 周报状态 {WEEK}：……"。
- [ ] 通知送达；平台没有通知能力时，最后输出能被调度脚本取到。
- [ ] 与其他平台同一周的产出对照：GitHub Top 5 的名次与 star 数应一致（由脚本决定）；②④⑤ 的选题可以不同，但都要通过质量门槛。
- [ ] 期间没有需要人工点"确认"的环节；如有，说明该平台的授权或沙箱配置还不够。

### 4.5 上线检查（每个平台正式启用前）

手动触发一次正式运行，检查：

- [ ] 周报在 `AI资讯/周报/{ISO 周年}/{WEEK}.md`，开头有元数据
- [ ] 数据文件在 `AI资讯/数据/github-weekly/{WEEK}.json`
- [ ] 状态文件在 `AI资讯/数据/运行记录/{WEEK}.json`，`python3 AI资讯/任务/scripts/trace_view.py --week {WEEK}` 能看到完整的时间线
- [ ] 收到通知，首句格式为"【AI周报 W..】……"，全文链接可以打开
- [ ] 通知的"运行结果"三行显示校验通过、全部完成、已推送到 `main`

### 4.6 多平台部署

- 各平台贴同一份入口提示词，不加角色参数；时间建议错开 1 小时以上，只是为了少等待。
- 正常情况：先到的运行，产出后释放锁；后到的看到"已产出"，用 `verify.py` 做独立校验，通过后本周完成；之后到达的读一次状态文件就退出。
- 后到的平台校验不通过时，会接过锁重跑，通知首句标"重跑"，正文写明原因。
- 先到的运行超过租约（默认 60 分钟）没有续期，后到的会接管重跑，通知首句标"接管"。
- 查看某周的协调过程：`python3 AI资讯/任务/scripts/coord.py status --week 2026-W45`，或 `trace_view.py --week 2026-W45`。

## 5. 回溯运行

在提示词前加一行 `TARGET_START=YYYY-MM-DD`（目标周的周一）或 `TARGET_WEEK=YYYY-Www`，即按回溯模式生成该周周报。榜单数据文件已存在时直接复用；不存在且已超出 Trendshift 每日数据的 61 天窗口时，③ 无法精确计算本周增量，要在数据说明中注明。回溯同样走协调锁，状态文件按目标周记录。

## 6. 故障排查

先看执行记录：`python3 AI资讯/任务/scripts/trace_view.py --week {WEEK} --errors`。错误码的含义：`python3 AI资讯/任务/scripts/tracelog.py codes`。

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `coord.py` 报 `PUSH_DENIED` | 运行环境没有推送 `main` 的权限（Claude 云端：定时任务没有挂载本仓库） | 配置推送凭证；Claude 云端在定时任务编辑页挂载仓库 |
| `coord.py` 报 `STATE_INVALID` | 状态文件被手工改坏 | 人工修复或删除该周的状态文件（走 PR），再手动触发 |
| 通知首句标"需人工" | 本周 3 次产出尝试都没通过 | 看 `trace_view.py` 找原因；修复后删除该周状态文件重跑，或手工补写 |
| 通知首句标"未提交"（`ACTION=lost`） | 运行太久，租约过期后被其他运行接管 | 一般不用处理，接管方会完成；频繁出现时调大 `runtime.yaml` 的租约 |
| 通知首句标"检查未通过" | 质量门槛改了 3 轮仍未通过 | 看数据说明和执行记录里的错误码；必要时手动触发重跑 |
| 通知首句标"降级" | 写作失败，提交了脚本生成的降级版 | 手动触发重跑；部署了多个平台时，后到的平台会自动校验不通过并重跑 |
| `GATE_SEARCH_MIN` 反复出现 | 模型没有按手册记录搜索，或搜索能力受限 | 检查平台的联网搜索设置；确认手册里的 `tracelog.py search` 被执行 |
| 原文读取大量失败 | 运行环境不允许访问任意网站，或站点拒绝程序访问（403） | 不影响运行：链接仍取自 HN 数据；需要摘要时由搜索补充 |
| 脚本报网络错误、`git push` 连不上 | 运行环境禁止命令联网（Codex 沙箱默认如此） | Codex 加 `-c sandbox_workspace_write.network_access=true`；其他平台放行第 2 节的站点 |
| `git` 报只读或 Operation not permitted | 部分沙箱默认保护 `.git` 目录 | 按平台文档放开 `.git` 的写权限；在已隔离的运行环境里，也可以改用 Codex 的 `-s danger-full-access` |
| 脚本报 TLS 或代理错误 | 环境网络策略拦截，或代理证书未配置 | 检查环境网络设置是否放行了这些站点 |
| OSS Insight 请求超时 | 接口偶发挂起 | `rank_github.py` 会重试；仍失败的仓库在数据文件 note 和数据说明中注明 |
| `collect_all.py` 输出 `trendshift_not_ready` | 周榜尚未生成（307、空列表或日期不符） | 手册已安排在其他步骤之后重试；连续出现时考虑推迟运行时间 |
| Trendshift 解析不到 ItemList 或每日数据 | 页面结构变化 | 在数据说明中记录，修订 `collect_trendshift.py` 的解析规则并补测试 |
| `check_run.py` 报"未完成" | 某一步没有在本次运行中做（跳过采集、没重新排名、没记录搜索、没运行 finalize） | 回到那一步补做，不要只改周报文字 |
| `check_portability.py` 报问题 | 执行文件里写进了平台专属的写法或直接的 git 操作，或入口提示词引用了手册步骤编号 | 把平台相关的内容挪到本文第 4 节；git 操作改用 `coord.py` |
