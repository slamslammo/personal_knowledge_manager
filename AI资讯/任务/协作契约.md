# AI 资讯任务协作契约

> 本文件规定 AI 资讯任务的开发、评审与上线由谁做、按什么门禁做、证据留在哪里。规则本身以 `方案.md` 为准，版本与变更原因见 `版本规划.md`，部署步骤见 `部署指南.md`。本文件只写协作方式，不写流程细节。

## 1. 角色

| 角色 | 职责 | 不做 |
| --- | --- | --- |
| 用户 | 提需求、定取舍、配置平台（定时时间、模型档位、仓库挂载）、决定上线与合并 | 不手工改状态文件；不在运行会话里改任务工程 |
| WorkBuddy（开发主力） | 调查取证、写提案、实现、补测试、开 PR、处理评审意见、跑验收 | 不直接推送 `main`（运行产出除外，见第 4 节） |
| Codex（独立评审） | GitHub 上的自动审查：方案可行性、边界与失败处理、代码与测试 | 不代替用户做取舍；不直接改仓库 |

Claude 此前承担开发与运行，2026-11 起订阅暂停，其历史角色由 WorkBuddy 承接；运行环境仍可继续部署在 Claude 云端定时任务，平台与开发工具解耦（见 `方案.md` 第 9 节）。

## 2. 门禁与顺序

```text
需求对齐（用户 + WorkBuddy）
      ↓ 提案文档入库 + 开 Draft PR
方案评审（Codex 自动审查 → 用户确认取舍）
      ↓ 按评审意见改提案，提案状态改为「已批准」
实现（代码 + 测试 + 验证结果，提交到同一 PR）
      ↓ PR 转 Ready for review
代码评审（Codex 自动审查，结论绑定提交 SHA）
      ↓ 逐项回应 → 合并
运行验收（用户触发一次正式运行，检查产出与状态文件）
```

- **方案评审通过不等于实现通过**：代码评审以最新提交为准，追加提交后要确认审查覆盖了新差异。
- 方案变更（范围、验收条件、失败处理有实质变化）要回到方案评审，不能只在代码里改。
- 合并由用户执行或明确授权；PR 描述里要写明「本轮已落地 / 未落地」。

## 3. 审查触发方式（2026-11-11 实况）

仓库已接入 Codex 的 PR 自动审查，机器人为 `chatgpt-codex-connector[bot]`。已观测到的触发点：

| PR | 触发动作 | 被审查提交 | 状态 |
| --- | --- | --- | --- |
| #4 | 创建 PR（`PR opened`） | `9e355e6` | 已完成，提出 5 项问题 |
| #6 | 草稿转待审（`Draft marked ready`） | `362396e` | 已完成，后续由 `e0e500f` 修复 |

由此确定的用法：

1. 方案与实现都在 Draft PR 里推进，准备好被审时再转 Ready for review。
2. **追加提交不保证自动复审**；需要复审时在 PR 评论 `@codex review`。
3. `Completed` 只表示审查执行完成，不代表无问题，也不等于已配置「审查通过才能合并」的强制规则；合并前要人工确认结论已落实。
4. 仓库侧的自动审查只读 GitHub 上的内容：只存在于聊天里的方案，它读不到。因此**方案必须先入库**（`提案/` 目录），这是它能看到方案的前提。

## 4. 谁能写什么

| 内容 | 写入方式 |
| --- | --- |
| `AI资讯/任务/`（方案、提案、配置、提示词、脚本、测试） | 只能走 PR，评审后合并 |
| `AI资讯/周报/`、`数据/github-weekly/`、`数据/运行记录/` | 由定时任务经 `coord.py` 直接推送 `main`，不需要人工确认 |
| `AI资讯/README.md` | 走 PR |
| 状态文件 `数据/运行记录/{WEEK}.json` | 只由 `coord.py` 写；人工修复需走 PR 并在提案里说明原因 |

运行会话（定时任务）只用于运行和诊断，不承担开发；开发在开发会话里做，成果经 PR 进入 `main`。

## 5. 证据要求

评审要能判断「问题是否真实存在」「意见是否落实」，因此每次提案与实现都必须带：

- **问题证据**：命令输出、文件行号、失败记录、复现步骤。没有证据的判断写成待验证，不写成结论。
- **验证结果**：单元测试数量与结果、`check_portability.py` 结果、必要的端到端或测试模式运行记录。
- **评审记录**：写进提案的「评审记录」表，含日期、评审方、结论、对应提交 SHA。

## 6. 本轮已知的协作约束

- 平台侧配置（定时时间、模型档位、仓库挂载、提示词粘贴）只有用户能改，仓库改动无法替代。凡此类动作，提案里单列为「平台侧动作」，并写明验收怎么查。
- 运行环境的 Python 依赖必须显式声明（`requirements.txt`），不能只写在文档里；CI 与本地都按同一份依赖安装。
