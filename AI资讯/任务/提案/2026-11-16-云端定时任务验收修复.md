## 修改

- 初始化授权与日常交付限制分开，允许必要的应用绑定、正常鉴权、实际工具状态目录写入；测试文档保留，bot 缺少文档权限不再是硬门槛。
- 环境检查分层：Python/PyYAML 与 Git 是核心；Node、CLI、飞书身份和网络是交付层。交付失效不阻断 Git 周报，环境升级时也适用。
- 核心缓存使用 `core_ready`，仍轻量检查本地核心依赖，不代表生产验收。机器检查另报 `DELIVERY` 和 `ACCEPTANCE=pending`。
- 出站改用真实 `auth status --verify`；文档正文由实际 user fetch 核对。
- 项目 `config/deployment.yaml` 默认 `acceptance`。固定入口运行项目即可自动进入沙箱，无需临时添加测试参数。验收通过不自动切生产。
- `deployment.py start` 自动建立本地沙箱；`finish` 核对实际发布提交、质量门槛、测试文档读回与通知隔离。正文转换差异报 pending，不能冒充一致。
- 文档/通知脚本直接识别项目验收模式；即使协调尚未启动、部署已失败，也跳过真实通知。非法模式保守隔离。
- `credential_probe.py` 留存非敏感观察记录，分别检查本次读取、不同实例、自然过期刷新、后继实例读取刷新状态。同用户重新扫码会重置观察，同机第二个进程不算跨实例。
