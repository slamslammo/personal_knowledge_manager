# 提案：运行平台三场景验证与定案

- 状态：**定案**（2026-11-17，用户确认）
- 背景：飞书实现与 W45 重跑评审（第二轮）通过后进入真实定时环境验证；2026-11-16/17 在三种候选运行场景实测，结论如下。本文档是运行平台选型的最终评估记录，**后续平台相关开发以此为准**。
- 关联：提案《2026-11-14-飞书接入与定时任务收敛》v4（其「单运行者=云端」的定案被本文修订）；部署指南 4.7/4.9/4.10/4.11 随本文同步修订。

## 1. 三场景评估

### 场景一：Codex 定时任务

**支持**：平台按计划启动 Agent，执行搜索、分析、写作和工具调用（计入订阅额度）；可使用任务可用的应用、连接器及插件，不限于 GitHub。

**验证与问题**：
- 曾生成 W46 周报，但**只存本地沙箱，未交付 GitHub 或飞书**。
- 后一次运行找不到此前沙箱——本地文件不跨运行保留（无直接证据表明每次新建 VM，但不能依赖）。
- 任务显示「继承环境」，未提供具体环境绑定；编辑界面没有密钥配置入口。
- 能读 GitHub ≠ shell git 有推送身份；本次任务缺写入凭据。
- 飞书扫码入口被自动审批拦截，应用绑定未完成。
- 定时任务如何继承、刷新并持久化飞书授权，未验证。

**结论**：Agent 生成能力已展示；**稳定的发布与飞书交付链路未通过验收**。

### 场景二：Codex 云环境

**支持**：可安装 CLI、运行脚本、配置服务访问并交互授权；已验证 user 文档操作、user/bot 鉴权与 access token 自动刷新；完整凭据恢复到新目录后能免扫码读文档（同机实验）。

**验证与问题**：
- 云环境的凭据**未被证明会传给 Codex 定时任务**。
- user 授权状态 = token + DPoP 私钥 + 本地解密密钥，只存 App ID / App Secret 不够。
- refresh token 实测约 7 天，不能保证每周运行一次就足够。
- 环境没有持续运行保证；安装 cron 不能保证按时执行，也不能唤醒被暂停的环境；**云环境存在外网访问受限问题**。
- 没有已确认的接口让 cron 直接启动本聊天 Agent；另行调用 Agent CLI / API 需要独立配置。

**结论**：适合**开发、评审和手动集成测试**；**尚不具备已验证的常驻定时执行条件**。

### 场景三：GitHub Actions

**支持**：定时、代码推送和手动触发；可自动安装 CLI，通过 Secrets 向脚本提供凭据；仓库已有测试工作流实跑成功。

**验证与问题**：
- 托管 runner 每个 job 新环境，不能依赖上次本地文件。
- 尚未在真实 runner 上验证飞书读写。
- 当前 GitHub 连接访问 Secrets 管理接口返回 403，凭据未上传。
- user token 刷新后 CLI 只更新 runner 本地文件；需另行实现并验证回写 Secrets。
- Actions 不会自动获得聊天 Agent / 订阅调用能力；拟议「生成端产出 + Actions 交付」仍待端到端验证。
- 也不能解决生成端缺少 GitHub 写入身份的问题。

**结论**：交付方案**有实现路径，但目前只有预研和部分组件验证，没有端到端验收**。

## 2. 跨场景发现

1. `personal_knowledge_manager` 是**公开仓库**：凭据绝不入库（现行设计已满足——凭据存 macOS 钥匙串与环境侧标记目录）。
2. 飞书 bot 建文档报 99991672 是**应用身份权限不足**，本机与云端结果一致，**并非云环境差异**（双端对照实测，提案 v4 附录 A.5 既有结论获复核）。
3. 本机网络偶发问题留档：2026-11-16 代理对 github.com 的 CONNECT 隧道间歇 502 约 4 分钟（api.github.com 同时正常），自愈未干预；待 netctl 排查，不影响平台选型结论。

## 4. 后续开发依据（本文档的用途）

1. **交付层已与生成层解耦**：`feishu_sync.py` / `env_check.py` 平台无关、纯标准库——后续换运行平台（云端或 Actions 突破任一阻塞项后）只需重做凭据初始化与定时触发，交付与验收资产直接复用（v4 提案 A.7 的预判成立）。
2. **三场景各自的阻塞清单**已固化在第 1 节（PAT 注入方式 / 凭据跨任务持久化 / 定时触发接口），后续任一平台突破，按部署指南 4.10 的收敛路径重新部署即可。
3. 凭据形态结论（token + DPoP 私钥 + 解密密钥、refresh ~7 天）是后续一切保活/托管方案的输入事实，不得再按「30 天」「只存 AppSecret」的旧假设设计。
4. 协作契约待办：本定案经用户确认后补 `方案.md` 决策记录与 `版本规划.md` 登记。
