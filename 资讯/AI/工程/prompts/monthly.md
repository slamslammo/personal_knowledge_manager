# 月报执行手册（草稿，未接入周报流程）

> 本手册为**静态草稿**，供后续迭代开发引用。当前周报流程不执行本手册；启用前须先完成「发布职责切分」（见 `文档/提案/2026-11-24-基于周报的月季报开发启动.md`）。

## 输入

- 目标月份 `YYYY-MM`，由入口参数给出；不带参数时按北京时间推算上一个已结束的自然月。
- 该月所有归属周（`core/weeks.py: weeks_in_month`）的**已发布周报**与每周榜单 JSON，统一从同一 Git 提交读取。
- 缺一份周报或榜单即列入缺项，不用空值补齐、不凑数。

## 期间口径

- **周四定月**：一份 ISO 周报连同新闻、洞察、榜单整份归入该周周四所在自然月；新闻保留事件原日期。
- 月报开头列出覆盖周编号；正文覆盖周数与榜单覆盖周数**分别计算**。
- 等最后一个归属周结束并发布后才定稿；未结束的期间单列，不出正式稿。

## 写作规则

按 `templates/monthly.md` 的六个板块写作：月度主线、关键时间线、月度 GitHub 榜 Top 10、话题演变、精选必读 5 篇、数据说明。

- 每条主要判断**可追溯到对应周报及原文**；引用官方一手源，社区讨论只作热度信号。
- 榜单从周榜明细按 `week_stars` 跨周累加、按仓库去重，列贡献周数与 `days_covered`；空值、未入榜、缺周榜均不当零，描述为「已存周榜样本的新增 star 合计」。
- 必读数量取 `config/ranking.yaml` 的 `monthly.must_read`（当前 5）。
- **不写主观概括作为标题**：标题固定 `AI 月报 · YYYY-MM`；趋势判断只出现在正文并标注证据等级。

## 校验与失败处理

- 生成后跑期间校验：元数据字段、覆盖周清单、榜单口径、链接可读性、缺项说明。
- 缺月报所依赖的周报时，输出待补周编号并停止，不生成半成品。
- 重跑同一 Git 输入应产出同一份覆盖清单与榜单；不覆盖其他月份的产物。
- 无法恢复的失败按入口规则生成失败通知：`【AI月报 YYYY-MM｜失败】<原因>`，写清停在哪一步、已完成什么；测试模式不发真实通知。

## 边界

- 本手册不授权写仓库：发布只经 `core/coord.py` 白名单造树，独立任务只写指定类型与期间的产物。
- 不重新采集历史数据；历史季度走专题回顾线，其口径见 `文档/2026-11-24-年度资讯档案展示规范与历史专题.md`。
- GitHub 期间新增 star 对无存档期间不可回溯，此时只写「本期无榜单」，不写数字。
