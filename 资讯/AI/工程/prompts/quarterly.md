# 季报执行手册（草稿，未接入周报流程）

> 本手册为**静态草稿**，供后续迭代开发引用。当前周报流程不执行本手册；启用前须先完成「发布职责切分」（见 `文档/提案/2026-11-24-基于周报的月季报开发启动.md`）。

## 输入

- 目标季度 `YYYY-QN`，由入口参数给出；不带参数时按北京时间推算上一个已结束的自然季度。
- 该季度**三份已发布月报**，沿月报的输入记录回查周报与榜单明细。
- 缺一份月报即列出待补月份并停止；三份齐备才生成一个季度。

## 期间口径

- **三个月成季**：季报汇总 Q1=(01/02/03月) 等自然季度，开头列覆盖的三份月报与归属周。
- 等季度最后一个归属周结束并发布后才定稿；未结束的期间单列。
- 正文覆盖周数与榜单覆盖周数**分别计算**；两轨口径（正式版 star 增量 / 回顾版上榜次数）不混排比较。

## 写作规则

按 `templates/quarterly.md` 的六个板块写作：季度主线、重点发布与技术方向、开源与产业趋势、回看上季判断、下一季度观察点、数据说明。

- 季度主线是**跨月才看得出的判断**，每条附支撑月报/周报条目与原文链接；归纳标注证据等级并接受人工核对。
- 「回看上季判断」逐条核对上季观察点：应验 / 未应验 / 证据不足；首期无上季季报时如实注明留空。
- 「下一季度观察点」须可验证且有依据，不写无依据预测。
- 季度 GitHub 榜从**三个归属月的周榜明细**重新累加，不复用三张月度 Top 10；记录贡献周数与 `days_covered`，空值/缺周/缺测不当零。
- 只有历史名次时单列上榜次数与名次，注明「回顾版口径」。

## 校验与失败处理

- 生成后跑期间校验：元数据、覆盖月/周清单、榜单口径、链接、缺项说明。
- 重跑复用同一期间产物；不覆盖其他季度的月报、季报或周报。
- 无法恢复的失败按入口规则生成失败通知：`【AI季报 YYYY-QN｜失败】<原因>`，写清停在哪一步、已完成什么；测试模式不发真实通知。

## 边界

- 本手册不授权写仓库：发布只经 `core/coord.py` 白名单造树，独立任务只写指定类型与期间的产物。
- 不重新采集历史数据；Q1–Q3 的历史专题季报是另一条产物线，不因本手册启用而改写。
- GitHub 期间新增 star 对无存档期间不可回溯，此时只写「本期无榜单」，不写数字。
