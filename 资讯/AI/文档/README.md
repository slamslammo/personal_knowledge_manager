# AI 资讯开发文档

开发与 PR 评审从这里进入；运行 agent 按 [工程入口](../工程/prompts/routine-prompt.md) → [执行手册](../工程/prompts/weekly.md) 运行，无需读取整段开发历史。

**先确认边界：工程、配置、提示词和文档改动走 PR，用户决定或授权合并；当期资讯产出由运行会话经 `coord.py` 直接推 main。** 实质规则变更先提案，已批准范围内的小修直接 PR，具体见 [协作契约](协作契约.md)。

## 开发与评审阅读顺序

1. [协作契约.md](协作契约.md)：修改权限、提案判断、一轮评审及最终版本检查。
2. 本次提案（如需）、PR 差异与对应 SHA 的验证记录。
3. 只读改动涉及的 [方案.md](方案.md) 章节及配置、源码、测试；涉及运行再读 [部署指南.md](部署指南.md)。
4. 需要追溯原因时，再查 [版本规划.md](版本规划.md) 和历史提案；不把全部历史作为默认上下文。

## 规则各放一处

| 内容 | 维护位置 |
| --- | --- |
| 内容要求、数据口径、架构与存储设计 | [方案.md](方案.md) |
| 修改权限、PR、验证与合并 | [协作契约.md](协作契约.md) |
| 当前平台/模式/调度安排、部署及恢复 | [部署指南.md](部署指南.md) |
| 运行授权与安全边界 | [routine-prompt.md](../工程/prompts/routine-prompt.md) |
| 运行命令、安装步骤、机器参数 | [weekly.md](../工程/prompts/weekly.md)、[env-bootstrap.md](../工程/prompts/env-bootstrap.md)、[config/](../工程/config/) |
| 路线、进度及变更缘由 | [版本规划.md](版本规划.md) |
| 单轮取舍、评审结论与实测证据 | [提案/](提案/README.md) |

修改规则时更新所属文档及对应实现，其余文档只链接，不复制整套流程。工程/配置改动核对最终 PR head 的 CI；纯文档 PR 受路径过滤而不自动跑 CI，验证口径见协作契约。

历史附件 `提案/附件/2026-11-15-TEST_RUN-W45/` 保留迁移前的 `AI资讯/...` 原始路径，不追改证据；当前结构见方案第 8 节。
