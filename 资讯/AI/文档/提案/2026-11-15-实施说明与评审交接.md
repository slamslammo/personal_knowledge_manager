## 发现与修复

- **重复创建和错误覆盖。** 新文档暂时搜不到，重跑曾重复创建。先核对缓存的文档 ID，再按规范标题检索所有分页。多个候选或缓存读回原因不明时停止写入，创建结果未明则保留待核记录。11-18 又补上分页未读完就停止写入的检查，并在多次重试后仍保留未决创建记录。[后续修复 PR #12](https://github.com/slamslammo/personal_knowledge_manager/pull/12)
- **测试文档标题。** 覆盖会按正文 H1 重置标题，测试前缀也写入 H1，覆盖成功后补全结果链接。
- **测试隔离和成功判定。** 交付脚本同时读取运行参数与协调状态的测试标记。解析 CLI 的业务结果和错误输出，部分写入或缺少文档 ID 时报告失败。补交付重新检查授权，通知发送结果不明时沿用原幂等键重试。
- **身份与代理。** 文档命令显式使用 user，通知使用 bot。清理失效的回环代理时保留仍可用的 HTTPS 代理，避免让云端请求绕过代理。
- **回溯稿的事实核对。** 补回漏选的高分文章，区分纯文本实验与允许执行 Python 的实验条件，修正旧文归因和洞察出处。修复提交新增 27 项回归，作者记录 185 项测试通过，并将订正稿同步到同一测试文档第 11 版。[修复提交](https://github.com/slamslammo/personal_knowledge_manager/commit/6b17ec8a085d47e96d36a7da06eb4616a0dbb9c9)

11-20 在 `1f6548c` 用模拟 CLI 复核时发现，已有文档读回失败仍可能导致补交付重复创建。复现条件与修复见[保留已知文档 ID 的 PR #20](https://github.com/slamslammo/personal_knowledge_manager/pull/20)。

同一 Codex 云会话中，user 的 access token 自然到期后，读取既有飞书文档成功。另起 CLI 进程查询时，状态已从 `needs_refresh` 变为 `valid`，access token 和 refresh token 的到期时间均已延后。独立定时任务能否继承刷新后的凭据仍待验证。[续期实测记录](https://github.com/slamslammo/personal_knowledge_manager/blob/baea77c72d292954e0981ced3adcef72596352cb/AI资讯/任务/提案/附件/2026-11-15-Codex-飞书评审/refresh-validation.json)
