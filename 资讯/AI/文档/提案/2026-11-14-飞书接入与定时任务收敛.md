# 飞书接入与定时任务收敛

2026-11-14 提出，11-15 定稿（v4）。目标是让读者在飞书看周报和接收通知，同时保留 Git 中可追溯的发布稿。 11-24 起采用[年度表索引](2026-11-24-年度资讯档案展示规范与历史专题.md)，以下保留当时选择 docx 的依据与验证。

## 采用的设计

- **先发 Git，再交付飞书。** 正式运行以采集前成功推送 Git 状态为前提。飞书文档授权失效只降级文档同步，通知授权失效只降级通知。授权恢复后按周和发布提交单独补交付，从该提交读取正文，避免把因人工修改保护而未入库的草稿发出去。
- **同一时间只启用一个运行端。** 实测用过期 revision 追加内容仍成功，无法靠它阻止旧任务写入。沿用 Git 协调锁。这把锁在发布时释放，切换运行端前还要确认旧端在途任务和飞书同步进程都已结束。
- **一周复用一篇文档。** 测试和正式分别按栏目与完整 ISO 周识别。普通稿改为回溯稿时仍复用同一篇，搜索候选经核对唯一才覆盖。创建请求超时后，搜索仍为空也可能是索引延迟，后续实现保留待核状态。[实施与验证](2026-11-15-实施说明与评审交接.md)
