# 月报、季报的发布权限与交付

2026-11-24 确认并合并初版，当日补齐按期间发布及年度表读回。[前期设计](2026-11-24-基于周报的月季报开发启动.md) · [初版 #35](https://github.com/slamslammo/personal_knowledge_manager/pull/35) · [完整发布链路 #37](https://github.com/slamslammo/personal_knowledge_manager/pull/37)

## 功能与授权的取舍

| 改动 | 决定和原因 |
| --- | --- |
| 写入产物 | 周、月、季各用独立入口和白名单。周报只提示期间到期与缺项；月季任务按类型和期间隔离工作目录，只提交本期报告。这样可以独立重跑一个月并保护其他期间的稿件。 |
| 来源和发布 | 准备时固定 Git 来源提交。发布前复核输入、区分缺正文和缺榜，推送后比对 Git 正文。同一期间、同一稿件可重跑；已有不同正文走修订 PR。 |
| 飞书交付 | #35 移除了例行创建和读回 docx 的权限，保留 bot 通知。#37 给索引脚本增加对已配置年度表的记录读写权限，使用发布提交更新并核对同一期间。索引或通知失败时保留 Git 发布结果。 |

原授权逐项差异可在[初版决定](https://github.com/slamslammo/personal_knowledge_manager/blob/4ecd0d7ed3d9ec6bf3acb296c7c93cbd4681c930/资讯/AI/文档/提案/2026-11-24-月报季报完整开发授权差异.md)核对。现行权限以仓库里的[周报入口](../../工程/prompts/routine-weekly.md)、[月报入口](../../工程/prompts/routine-monthly.md)、[季报入口](../../工程/prompts/routine-quarterly.md)为准。
