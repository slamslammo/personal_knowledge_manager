# AI 周报运行平台选择

2026-11-17。生成周报需要能搜索和写作的 Agent，交付还需要 Git 写入身份和可持续使用的飞书授权。三种候选环境的验证结果决定了主运行端的选择。

| 候选环境 | 当时的验证结果 | 对周报的影响 |
| --- | --- | --- |
| Codex 定时任务 | 曾生成 W46 并提交到本地沙箱。后一次运行找不到该沙箱。界面显示「继承环境」，本次任务缺 Git 推送身份，飞书扫码绑定被审批拦截。 | 已展示 Agent 生成能力，跨运行文件与凭据继承、生产交付仍待验证。两次观察无法确定每次是否新建虚拟机。 |
| Codex 交互云环境 | user 文档操作、user/bot 鉴权、access token 刷新成功。同机将完整凭据恢复到新目录后可以免扫码读取。 | 可做开发和手动集成测试。常驻运行、cron 唤起聊天 Agent、凭据传给定时任务均未取得验收结果。 |
| GitHub Actions | 仓库 CI 已实际运行。托管 runner 按 job 分配，本次访问 Secrets 管理接口返回 403，未在真实 runner 验证飞书交付。 | 作为候选交付端，还需安全注入凭据和保存刷新后的状态。生成端的 Agent 调用及 Git 写入身份须另行解决。 |

**飞书身份与续期。** 同一应用的 bot 在本机和云端建文档都报 `99991672`，由 user 建文档、bot 发通知。user 授权涉及 token、DPoP 私钥和本地解密密钥。一次实测的 refresh token 有效期约 7 天，与周报间隔接近，跨任务续期和刷新状态继承仍需独立观察。

**决定与后续调整。** 11 月 17 日选定 WorkBuddy 本机为唯一运行者，当时计划每周一运行，接受设备须开机并登录的条件，漏跑可指定报告周回溯。11 月 18 日维护者批准切换生产，并明确由用户手动触发。Codex 用于开发与评审，Actions 运行 CI。当前启停安排见[部署指南](../部署指南.md)，当时的排程与实验记录见[原始提案](https://github.com/slamslammo/personal_knowledge_manager/blob/b4e1607c628a2a2982c6fc23afbd5fb0640931b2/资讯/AI/文档/提案/2026-11-17-运行平台三场景验证与定案.md)。
