# W45 目录迁移与生产发布复盘

2026-11-18 · 目录迁移已完成。W45 回溯版已发布到 Git，正式飞书文档已读回核对。

## 为什么迁移

原来的 `AI资讯/` 同时承担板块入口、任务工程和产出存储，路径分散，新增资讯板块时也难以复用。迁到 `资讯/AI/` 后，README 负责导航，`工程/` 放执行文件，`文档/` 放开发资料，`数据/` 放发布产物。任务的读写权限按目录划分，原有数据子目录沿用。脚本通过 `paths.py` 生成产出路径，并向上查找 Git 根目录。[迁移提交](https://github.com/slamslammo/personal_knowledge_manager/commit/6c8d55b7cd9b70acf92682a137de7860f94935c0)

## 问题与修复

| 问题 | 原因与处理 |
| --- | --- |
| 沙箱中断后无法重跑 | 裸仓库可能只有目录、没有分支。重入时校验并补齐缺失引用，保留已发布的沙箱提交。 |
| 迁移后首发误判人工改稿 | 保护逻辑把周报的纯重命名当作正文编辑，发布质量被降为 `check_failed`。沿目标文件历史跳过 `R100` 纯重命名，仍保护真正的人工修改。用本地 Git 样本即可复现。 |
| 飞书读回误判正文相等 | 单行 HTML 要还原成块才能比较。初版通过了 W45 样本，却漏掉 URL 字符变化、链接退化为文字和表格末尾的空单元格丢失。后续修复保留链接和表格结构，并为生产稿加上按发布提交读回的独立检查。[修复 PR](https://github.com/slamslammo/personal_knowledge_manager/pull/12) |
| 两次 CI 失败 | 一次测试依赖开发机 Git 身份，另一次验收用例读取了项目真实运行模式。测试改为显式传入身份、固定验收模式，并另测生产分支。生产发布早于该配置对应的 CI 结果，修复后 287 项测试通过。[CI 记录](https://github.com/slamslammo/personal_knowledge_manager/actions/runs/44221613622) |

文件树一度仍显示旧目录，当时通过实际文件列表核实了迁移。作者也报告推送时多次遇到代理 502，缺少原始日志，故障归属和等待时间无法核验。提交时间跨度约两小时，缺少分项计时和 token 明细。此次可避免的返工是为定位发布逻辑而重跑整周。迁移后先用小型 Git 样本验证发布逻辑，切换生产前核对最终提交的 CI。
