## 问题与取舍

2026-11-20 与维护者对齐定案：① 定时任务由提示词驱动、环境由部署引导初始化——维持现状；② 周报串联的确定性收归脚本（三段式），agent 只做判定、搜索、写作、返工改稿，失败重试用尽即告警退出，定位修复归开发流程；③ 月报、季报拆出周报流程为独立任务，各有独立入口提示词；④ 工程分层落到目录结构。整体 review 印证的 `coord.py` 职责过宽、补交付双路径等问题随本次一并收敛。

**范围**：本次完成周报侧全部（结构迁移、coord 质量拆分、三段式、手册瘦身、沙箱验收）；月/季报只做占位与规划。**不在本次**：月报季报实现与模板、`AI_WEEKLY_TMP` 清理、tests 跟随模块拆分。

## 解决办法

### 1. 目标结构与脚本归属

```
资讯/AI/工程/
├── core/          # 报告无关基座
├── weekly/        # 周报专属（含新增 prepare.py / deliver.py）
├── monthly/ · quarterly/   # 占位 README + 开放问题，后续迭代填充
├── tests/         # 15 个测试文件，自 scripts/tests/ 上移，保持集中
├── prompts/       # routine-weekly.md（改名）· weekly.md · env-bootstrap.md
├── config/ · templates/
```

**core（14）**：`paths` `common` `weeks` `workdir` `tracelog` `coord` `validate` `quality`（新）`document_compare` `feishu_sync` `env_check` `credential_probe` `trace_view` `check_portability`
**weekly（11）**：`collect_all` `collect_trendshift` `collect_hn` `collect_hf` `fetch_articles` `rank_github` `draft` `finalize` `check_run` `verify` `deployment`

归属依据（实测 import）：`coord.py:799` 延迟 `import validate` → 同在 core；`check_run.py:41–44`、`deployment.py:65`、`verify.py:22–26`、`draft.py:24–25` 的依赖链 → weekly 内同目录 + 对 core 正向。**跨目录只允许 weekly→core 单向**：weekly 模块头部统一注入 core 路径（tests 已有同款先例）；`check_portability.py` 新增守卫「core 不得 import weekly」。

### 2. 改名与引用同步

`routine-prompt.md` → `routine-weekly.md`，8 处引用同步（`部署指南.md:5`、`开发规范.md:9`、`工程结构.md`×3、`weekly.md:4`、`fetch_articles.py:3`、`check_portability.py:81/94` 改 `routine-*.md` 通配、`task.yaml:13`）。入口内 `scripts/` 路径改 `core/`。手册 `$S=资讯/AI/工程`，命令按归属加 `core//weekly/` 前缀（30+ 处机械替换）。CI discover 路径改 `资讯/AI/工程/tests`。

### 3. coord 质量推导拆分（行为不变重构）

`report_is_degraded`（coord.py:792）、`publish_gate`（:820）、`derive_quality`（:842）、override 判定（:851）、`mark_gate_unverified`（:868）、`publish_message`（:886）迁入新模块 **`core/quality.py`**——不能放 `check_run.py`（weekly），否则 coord（core）反向 import weekly，违反单向规则。`coord` 回归纯协调（锁、状态机、白名单造树、推送），`cmd_publish` 只调质量接口拿 `(quality, codes)`。`GATE_SCRIPT`（coord.py:817）随迁移更新路径。`test_coord.py` 对应用例同步迁移。

### 4. 三段式串联（本次行为核心）

| 段 | 入口 | 内容 |
|---|---|---|
| A | `python3 资讯/AI/工程/weekly/prepare.py` | 聚合第 0 步全部（workdir/deployment/weeks/preflight/coord 启动）+ `collect_all` 采集。ACTION 分流程序化：run→继续、wait→内置轮询（沿用 `wait_poll_seconds`/`wait_max_minutes`）、verify/exit/blocked→输出转交标记由入口规则处理。**trendshift 未就绪的穿插重试收进脚本内置等待**，用尽→结构化失败退出。输出：摘要 + 待 AI 判定清单 |
| 智能段 | 模型 | AI 判定写 `judgments.json` → 跑 `rank_github.py` → 联网搜索（每次 `tracelog.py search` 留痕）→ `draft.py` 占位符填写与写作 → 按 CODES 返工改稿 |
| B | `python3 资讯/AI/工程/weekly/deliver.py` | `finalize → check_run`；CODES 非空→输出返工提示退出（模型改稿后重跑，≤3 轮，轮次读 coord 状态）；通过则 `coord.publish → feishu_sync sync → verify → notify → workdir archive`。**任一环节脚本内重试用尽 → 生成失败通知文件 + 调 `feishu_sync notify` 告警退出**；平台无 lark-cli 时输出失败文本由调度方兜底。修复归开发流程 |

既有子命令全部保留（不删旧入口，旧命令在补交付/排障时仍可用），手册主链路切换为三段式。

### 5. 手册瘦身与任务同步

`weekly.md` 保留五原则、②–⑤/洞察/数据说明写作规则、返工映射表、通知文本格式；流程步骤收敛为「跑 prepare → 智能段 → 跑 deliver」。`routine-weekly.md` 同步微调（无授权/安全规则变更；若有，PR 单列 diff）。手册改版合并后**沙箱验收（TEST_RUN 实跑一轮）**为启用前置；随后按维护约定把新入口全文手动同步进「AI 资讯周报」周期任务 prompt（先合并后同步，回退先回滚任务）。

### 6. 月/季占位（不开发）

`monthly/README.md`、`quarterly/README.md`：用途、已预留复用点（`weeks.py` 到期判定、`paths.MONTHLY_RE/QUARTERLY_RE`、coord 白名单、feishu_sync 查重参数化点）、待月报提案定夺的开放问题（采集边界、校验骨架参数化上提、`routine-monthly.md` 创建时机、三入口安全规则逐字节一致检查）。
