# AI 周报部署与排障

## 当前运行

**WorkBuddy 是唯一运行端，当前生产由用户在本机手动触发。** 运行时保持设备开机、WorkBuddy 登录和网络可用。GitHub Actions 只跑 CI。实际模式以 [deployment.yaml](../工程/config/deployment.yaml) 和 `deployment.py plan` 的 `RUN_MODE` 为准。手动触发沿用 [固定入口](../工程/prompts/routine-prompt.md)，进入 [执行手册](../工程/prompts/weekly.md)，记录平台 `workbuddy`。开发改动走 [维护指南](README.md)。

## 环境与授权

在仓库根目录运行 `python3 资讯/AI/工程/scripts/env_check.py check`。确认运行端的 PATH 能找到 Git，实际使用的 Python ≥3.10 且已安装 PyYAML。安装方式、版本和配置步骤见 [env-bootstrap.md](../工程/prompts/env-bootstrap.md)。

- **Git 与网络**。优先复用该仓库的现有写入身份。缺权限时由用户在平台安全设置提供仅本仓库所需的写入身份。dry-run 是初筛，以协调脚本实际推送为写入证据。保留有效代理、CA 和 TLS 校验，分别核对 GitHub、采集来源和飞书的可达性与权限。
- **飞书**。Node.js 和 lark-cli 用于交付。复用「小龙虾1号」`cli_a92390bc96f9dbb4` 和已授权的同一 CLI 配置。文档用 user，通知用 bot。缺配置时按部署引导给出官方链接或二维码，由本人选择已有应用并完成授权，再回到同一环境完成凭据保存。凭据只通过平台安全设置或官方授权流程提供，禁止回显或入库。遇审批拒绝按实际限制报告。
- **跨任务凭据**。启用无人值守前，检查 CLI 实际配置和数据目录能否安全持久化并回写刷新结果，包括加密主密钥与 DPoP 状态。按部署引导用 `credential_probe.py` 核对独立任务免扫码读取、自然到期后首次 API 刷新、后续任务继承刷新结果。非敏感观察与凭据分开保存。

## 验收与切换

| 场景 | 如何判定 |
| --- | --- |
| 首次沙箱验收 | `env_check.py check --require-delivery` 通过后才开始新生成。核对质量检查、沙箱提交和 `[测试]` 文档读回，检查通知预览并保留 `deployment.py finish` 结果。采用 [执行手册的测试模式](../工程/prompts/weekly.md#运行模式)，保存的入口保持固定。 |
| 正式交付 | 分别记录 Git 发布 SHA 与质量结论、飞书文档 ID 与正文核对、通知 API 收据和接收人确认。核心依赖或 Git 写入失败时停止生成，飞书缺项时按手册降级，已发布 Git 周报可以单独补交付。 |
| 长期运行或换平台 | 先在目标平台做沙箱验收。用户决定何时正式运行和是否启用调度。切换前暂停旧端的触发、队列与重试，确认在途任务及飞书同步子进程全部结束。凭据续期和真实定时触发需在对应平台单独留证。 |

核心就绪标记仅缓存依赖检查。Git 锁在发布时释放，切换时务必确认飞书也已结束。沙箱通知按规则跳过。沙箱结果、GitHub 写入、正式收件和跨任务刷新逐项报告。

## 补交付

保留原工作目录、ISO 周、运行模式和收据。同周已有 Git 发布或本地沙箱时，只恢复交付。命令在对应运行环境的仓库根目录执行。

- **已有沙箱**。配置和授权齐备后，按 [执行手册](../工程/prompts/weekly.md) 的恢复分支运行 `deployment.py resume`。`RESUME=pending` 时保留产物并解决缺项，`RESUME=not_available` 时先核对模式与原沙箱是否仍在。
- **已发布 Git 稿**。从 `ACTION=published` 的输出取完整 SHA。找不到原输出时，查已同步的 `main` 上该周周报和状态文件的提交记录，用 `git show` 核对该提交里的周报和 `produced` 状态。无法确认发布稿时先停在诊断。确认后替换下列占位符，同步返回 `created` 或 `updated` 后执行第二行。

```bash
python3 资讯/AI/工程/scripts/feishu_sync.py sync --from-published --sha "<完整发布SHA>" --week "<YYYY-Www>"
python3 资讯/AI/工程/scripts/feishu_sync.py verify --sha "<同一完整SHA>" --week "<同一YYYY-Www>"
```

只有 `READBACK=passed` 才报告正文一致。临时读回失败先重试 `verify`，独立核对可指定 `--doc`。该命令只读飞书，会写本地核对记录。已发布的 W45 可用以下命令核对正文，其历史结果见 [W45 复盘](提案/2026-11-18-迁移与生产发布复盘.md)。

```bash
python3 资讯/AI/工程/scripts/feishu_sync.py verify --sha b8f21af481fbf17c039492d3fc69e48705f35831 --week 2026-W45 --doc QQVddhrEqolEfmxMKV9ce60inTb
```

- **新建结果不明或多候选**。保留 `feishu.json` 与原上下文。搜索为空、分页不完整或接口失败时，维持待核状态。唯一命中时可复用，多候选时先人工确认，禁止清掉待核记录后再次创建。
- **通知结果不明**。先找接收人确认。需要重试时按 [通知步骤](../工程/prompts/weekly.md#第-6-步通知) 使用原通知文件、原周与原模式，保留相同幂等键。原文件丢失时先报告。
