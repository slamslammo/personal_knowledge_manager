### 核心摘要规范（本次修正的重点）

维护者指出旧值「专题回顾版季报（本地草稿，未提交）…正文/榜单覆盖均 0 周」**言之无物**，无法一眼抓住重心。定稿规则：

| 项 | 规范 |
| --- | --- |
| 内容 | 「关键信息」写 **3–5 条该期间最有信息量的核心事实或结论**，用 `①…②…③…` 分隔；每条含事件名 + 日期 + 可核验信号（HN 分数 / 官方发布） |
| 禁止 | 不写"本地草稿/未提交/覆盖 0 周/报告尚未生成"这类**元信息**；不写"待补""无数据"作为摘要 |
| 元信息归位 | 草稿状态、覆盖周数、缺项等放 `正文覆盖周数`/`榜单覆盖周数`/`状态`/`备注` 字段，不占摘要 |
| 标题 | 固定 `{期间} · {层级}汇总`（`01月 · 月度汇总` / `Q1 · 季度汇总`），**只做期间标识，不写主观概括** |
| 报告链接 | 仅填对应期间报告在 GitHub 的 blob 链接；报告未生成时留空，不填本机路径 |
| 证据等级 | A=可核验事实（官方原文/带时间戳检索）；B=多源归纳需人工确认；C=推测不写数字 |
| 其他 | 正文/榜单覆盖周数分开算，空值、未入榜、缺周榜均不当零 |

以上规范已写入飞书字段 `description`（8 个字段）。视图列 `关键信息` 须可见（用 `+view-set-visible-fields`）。

## 三、月报 / 季报形式（定稿）

模板位于 `资讯/AI/工程/templates/`（本次先落 `monthly.md`/`quarterly.md` 初版，供后续开发引用），元数据沿用周报 YAML 风格。

### 月报

```yaml
---
month: 2026-10
weeks: [2026-W40, 2026-W41, 2026-W42, 2026-W43, 2026-W44]
coverage: {正文: 5周, 榜单: 5周}
quality: full | 专题回顾
source: ...
status: ...
---
```

正文板块（依 `方案.md:69-72`）：

1. **月度主线** — 3–5 条一句话结论，每条附支撑周报条目 + 原文链接；
2. **关键时间线** — 按事件原日期排列，跨月周整份归本月但**新闻保留原日期**；
3. **月度 GitHub 榜 Top 10** — 从周榜明细按 `week_stars` 跨周累加、按仓库去重，列贡献周数与 `days_covered`；口径写"已存周榜样本的新增 star 合计"，空值/缺周/缺测不当零；
4. **话题演变** — 新增 / 延续 / 消退，各附代表周；
5. **精选必读 5 篇** — 从各周洞察的必读里选（`ranking.yaml: monthly.must_read: 5`）；
6. **数据说明** — 覆盖清单、缺周/缺榜、来源提交、可疑内容、证据等级。

### 季报

```yaml
---
quarter: 2026-Q4
months: [2026-10, 2026-11, 2026-12]
coverage: {正文: N周, 榜单: M周, 月报: K/3}
quality: full | 专题回顾
---
```

正文板块（依 `方案.md:73-76`）：季度主线（3–5 条跨月判断）→ 重点发布与技术方向（按方向归类）→ 开源与产业趋势（季度榜从三个月周榜明细重新累加，**不复用三张月度 Top 10**）→ 回看上季判断（首期缺则注明）→ 下季观察点（可验证、须有依据）→ 数据说明。

### 归属口径

**周四定月，三个月成季**：一份 ISO 周报连同新闻、洞察、榜单整份归入该周周四所在自然月；月报开头列覆盖周编号，季报开头列覆盖三份月报。实测 `weeks.weeks_in_month(2026, m)`：全年 53 周各归属一次、无重复；2 月 4 周、10 月 5 周、12 月含 W53。

## 四、历史专题产物（本次补齐，均为真实检索）

产物路径：`资讯/AI/数据/月报/2026/2026-01.md` … `2026-09.md`（9 份）、`资讯/AI/数据/季报/2026/2026-Q1.md` / `2026-Q2.md` / `2026-Q3.md`（3 份）。

- **数据来源**：HN Algolia `created_at_i` 时间窗实测（Q1 数据 `/tmp/q1_hn.json`、Q2/Q3 `/tmp/q23_hn.json`），每月 AI 相关高分帖 16–34 条；官方发布链接取自检索结果的 `url` 字段，抽样实测 HTTP 200（Opus 4.6、GPT-5.3-Codex、GPT-5.4、Sonnet 4.6 等）；**HN item 链接全部为真实 `objectID`**。
- **证据分级**：A 级（可核验事实）入正文与关键时间线；B 级（趋势归纳）只在季报「季度主线」并标注待人工核对；C 级（GitHub 期间热度）明确不可得，不写 star 数字、不列名次。
- **口径诚实**：历史无正式周报与榜单存档，故元数据 `coverage: {正文: 0周, 榜单: 0周}`、`quality: 专题回顾`、`status: 待人工核对`；HN 分数是**讨论热度代理指标**，不是项目热度榜。
- **两处修正**（避免事后叙事）：① 「claw 年初带火 agent」实测集中在 1/26–2/21，不是年初；② 「muse 个人助理」在 Q1 无一手证据（检索全为博物馆），**实际出现在 2026-08-10 的 `Muse Glimmer: 30B-parameter model optimized for always-on local agent workflow`（HN 1209）**，Q3 季报已写入，不回写 Q1。
- **回看链条**：Q2 季报逐条核对 Q1 的 4 个观察点，Q3 季报核对 Q2 的 3 个议题——保持"当季判断 → 下季验证"的可追溯性。

## 五、基于周报的月报/季报方案定稿（后续开发依据）

适用于 Q4 及以后有正式周报的期间，与历史专题线分开：

1. **输入**：归属期内所有已发布周报（`git show <SHA>:<path>`）+ 每周榜单 JSON + 运行记录；缺一份月报即列待补月份，不凑数。
2. **发布职责切分（前置）**：改 `prompts/weekly.md:159` 让周报只提示到期/缺项，收紧 `core/coord.py:772-773` 白名单；验收加「周报运行不产生月报产物」。
3. **三套独立入口**：`routine-monthly.md` / `routine-quarterly.md` + 各自手册与任务标记；安全规则三份内联且逐字节一致（`check_portability.py` 断言）。
4. **运行时隔离**：按 报告类型＋期间 的独立工作子根，内部复用 `paths.FILES` 固定文件名；归档按期间；飞书标题参数化；发布白名单按类型收紧。
5. **榜单口径**：从周榜明细重新聚合（13 周 `week_stars` 累加，不复用月度 Top 10），记录贡献周数与 `days_covered`；正文/榜单覆盖率分开算；有 star 走正式版，只有名次走回顾版并分开标注。
6. **阶段二交付源收敛**：`deliver.py` 去掉 docx `sync/verify`，发布收据校验通过后写一行表格索引；`deployment.py` 验收读回改为核对沙箱 Git 提交正文；入口授权删除"创建/更新飞书文档"（PR 单列差异供确认）。保留 `notify` 与 `preflight`。
7. **验证**：模板与手册落库 → 期间校验 → 2026-10 沙箱样稿（W40–W44 五篇周报 + 五份榜单齐全）→ 人工核对漏收/重复 → 季报 → 离线全量 CI + `TEST_RUN=1` 沙箱验收。
