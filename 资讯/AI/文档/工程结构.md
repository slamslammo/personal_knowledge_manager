# AI 资讯工程结构

> 面向：第一次接手代码、需要了解「有哪些文件、各管什么、彼此怎么串起来」。
> 范围：`资讯/AI/工程/` 下的代码、配置、提示词、模板与离线测试。

约定先行（判断代码是否合理时对照这几条）：

- **确定性交脚本，判断力交模型**：路径、文件名、格式、校验、清理、归档由脚本产生；模型只负责核实来源、选题、分析、写作。
- **路径单一真值源**：`paths.py` 定义运行时根与固定文件名，`workdir.py` 是查询/清理/归档的唯一入口。
- **发布白名单**：`coord.py` 用独立 `GIT_INDEX_FILE` 造树提交，不改工作区、不 `git add -A`。
- **运行时数据在仓库外**：默认 `<仓库检出目录父级>/.ai-weekly/`，不入库。

## 1. 目录总览

[工程入口](../工程/README.md)列出开发依赖和测试命令。`weekly/` 实现周报专属流程，`core/` 提供共享工具、月季报发布和年度表更新。`monthly/`、`quarterly/` 的 README 分别链接到对应手册。各期正常产出的范围见[现行方案](方案.md)。

## 2. 运行流程与模块依赖

三段式运行入口：`weekly/prepare.py`（准备+采集）→ 智能段（判定/排名/搜索/写作）→ `weekly/deliver.py`（检查/发布/交付/归档），详见执行手册；旧子命令保留供补交付与排障。

周报模块从 `weekly/` 导入 `core/`，由 `check_portability.py` 检查导入方向。月季报的编辑发生在 `core/period_report.py` 两次调用之间。

```
L0 纯基础（不依赖工程内模块）
    paths.py, document_compare.py
L1 公共基座
    common.py → paths
    tracelog.py → common
    weeks.py → paths（延迟 common，避开环）
    workdir.py → paths, common
    trace_view.py → paths, tracelog, common
    check_portability.py → common
L2 采集与排名
    collect_hf / collect_hn → common, weeks
    fetch_articles → tracelog, common
    collect_trendshift → common, weeks, rank_github
    rank_github → paths, tracelog, common, weeks
    collect_all → collect_hf/hn/trendshift, fetch_articles, tracelog, common, weeks
L3 写作与校验
    finalize → tracelog, common
    draft → collect_all, finalize, tracelog, common
    validate → common, weeks
    check_run → tracelog, collect_all, common, finalize, validate, weeks
    verify → collect_hn, coord, tracelog, common, finalize, validate, weeks
L4 协调与发布
    coord → paths, tracelog, common, quality
    quality → validate（延迟导入）；子进程调用 weekly/check_run
L5 交付与部署
    feishu_sync → paths, tracelog, common, weeks（延迟 document_compare）
    env_check → common, feishu_sync
    credential_probe → feishu_sync, common
    deployment → common（启动时调用 env_check；验收读取本地 Git blob 并运行 check_run）
    annual_index → feishu_sync, paths, common, weeks
    period_report → annual_index, period_aggregate, coord, paths, weeks
```

quality 通过子进程调用周报检查器。Python 模块的导入方向与运行时的调用方向应分别核对。

### 核心调用链（一次正常周报）

```
routine-weekly.md
  → weekly.md（段 A → 智能段 → 段 B）
  → [准备] workdir.py print/check · deployment.py resume/plan · weeks.py > week.json
           feishu_sync.py preflight · coord.py start/wait/renew
  → [采集] collect_all.py（内含 4 个采集脚本）→ materials.json / digest.md / collect_report.json
           rank_github.py → 数据/github-weekly/{WEEK}.json
  → [写作] draft.py → 草稿 + draft.json（模型填 {{ }}、核实来源、写作）
  → [检查] finalize.py → check_run.py（内部 validate.run_checks）→ checks.txt
  → [发布] coord.py publish → 白名单造树 → push → 运行记录/{WEEK}.json
  → [交付] annual_index.py 按 Git 提交写入并读回当周年度表记录
           feishu_sync.py notify 发送通知
  → [归档] workdir.py archive --week → archive/{WEEK}/ + MANIFEST.json
  旁路：tracelog.py 全程写 trace.jsonl / searches.txt
```

---

### 月报和季报

1. [period_report.py](../工程/core/period_report.py) `prepare` 取目标分支的提交，月报读取按周四归属的周报，季报读取三份正式月报。[period_aggregate.py](../工程/core/period_aggregate.py)按本期实际覆盖的周榜计算数据。
2. 脚本输出本期工作目录。编辑者读取 `materials.md`、`board.md` 和 `inputs.json`，在 `body.md` 写分析。工作目录按类型、期间和运行模式隔离。
3. `publish` 再核对来源版本，校验正文和榜单，在目标分支只发布当期报告。同稿重试复用原提交，已有不同稿件通过 PR 修订。正式发布后更新年度表、发送通知；沙箱只保留本地提交、成稿和通知预览。[月报手册](../工程/prompts/monthly.md) · [季报手册](../工程/prompts/quarterly.md)

## 3. 核心脚本与依赖

「相关性」列格式：`依赖 → 被依赖`（均为工程内模块）；「状态文件」指 `WORK_DIR` 下读写的关键文件。

### 3.1 基础与运行时（先读这 5 个）

| 文件 | 作用 | 相关性 | 状态文件 | 测试 |
| --- | --- | --- | --- | --- |
| `paths.py` | 仓库产出相对路径 + 运行时根 + `FILES`/`CLEAN_PRESERVE`/`ARCHIVE_EVIDENCE` 单一真值源 | 无 → `common` `weeks` `workdir` `coord` `rank_github` `feishu_sync` `trace_view` | 自身不读写，只定义常量 | `test_runtime_paths.py` |
| `common.py` | 固化 `REPO_DIR`/`WORK_DIR`/`OUT_DIR`；`load_config`/`read_json`/`write_json`/`fetch`/URL 规范化 | `paths` → 几乎全部脚本 | 定义 `OUT_DIR`；读 `config/*.yaml` | 无独立测试，`test_collect.py` 仅测 2 个函数 |
| `tracelog.py` | 事件追加留痕 + 搜索计数 + 统一错误码表 `ERROR_CODES` | `common` → `coord` `collect_all` `fetch_articles` `rank_github` `draft` `finalize` `check_run` `verify` `feishu_sync` `trace_view` | 写 `trace.jsonl` `searches.txt`；读 `coord.json` 取 run_id | 无独立测试 |
| `weeks.py` | ISO 周编号、报告周推算、月/季归属与到期判定 | `paths`（延迟 `common`）→ `collect_all` `collect_hn/hf/trendshift` `rank_github` `validate` `check_run` `verify` `feishu_sync` | stdout 由手册重定向为 `week.json` | `test_weeks.py` |
| `workdir.py` | 运行时目录唯一入口；clean 先归档再按保留清单清理，archive 按周写 `MANIFEST.json` | `paths` `common` → 无（由手册以子进程调用） | 读写 `week.json` `coord.json` `deployment.json` `feishu*.json` `MANIFEST.json` | `test_runtime_paths.py` |

### 3.2 协调、发布与校验

| 文件 | 作用 | 相关性 | 状态文件 | 测试 |
| --- | --- | --- | --- | --- |
| `coord.py` | 协调锁 + 状态机；发布门槛、`quality` 推导、`GIT_INDEX_FILE` 白名单造树提交 | `paths` `tracelog` `common`（延迟 `validate`）→ `verify`；子进程调 `check_run` | 读写 `coord.json`；写 `coord.index` `sandbox.git` 与 git 内状态文件 | `test_coord.py` |
| `check_run.py` | 确认各步产物齐备且属本轮，并调 `validate.run_checks` 跑全部质量门槛 | `tracelog` `collect_all` `common` `finalize` `validate` `weeks` → `deployment`（延迟）、`coord`（子进程） | 读 `week.json` `coord.json` `draft.json` `collect_report.json` `materials.json` `judgments.json` `searches.txt` | `test_check_run.py` |
| `validate.py` | 校验结构、元数据、链接、榜单与 HN 数字；`run_checks` 是 4 条链路共用入口 | `common` `weeks` → `check_run` `verify` `coord`（延迟） | 默认读 `materials.json`；读仓库内周报/数据文件 | `test_validate.py` `test_gates.py` |
| `verify.py` | `ACTION=verify` 分支：重跑校验、重采 HN 对照数字、检查 ②④ 链接可达性 | `collect_hn` `coord` `tracelog` `common` `finalize` `validate` `weeks` → 无（手册调用） | 写 `verify/report.md` `verify/data.json` `verify/hn.json`；经 `coord.main(record)` 回写状态 | 无独立测试；`test_coord.py` 仅测 `override_conflict` |
| `document_compare.py` | 旧 docx 链路的 Markdown 读回比对 | `feishu_sync` 的旧命令使用；现行年度索引见 `annual_index.py` | 不读写文件 | `test_deployment.py` |
| `check_portability.py` | 静态扫描平台专属词、手册里的 git 写操作、入口提示词是否引用步骤编号 | `common` → 无（CI/本地调用） | 只读源码 | `test_portability.py` |

### 3.3 采集与排名

| 文件 | 作用 | 相关性 | 状态文件 | 测试 |
| --- | --- | --- | --- | --- |
| `collect_all.py` | 采集总调度：串起 4 个采集脚本，统一重试/跳过/留痕 | `collect_hf/hn/trendshift` `fetch_articles` `tracelog` `common` `weeks` → `draft` `check_run` | 写 `materials.json` `digest.md` `collect_report.json` 及各源 JSON | `test_collect_all.py` |
| `collect_trendshift.py` | Trendshift 周榜与各仓库 7 天每日 star/fork，附往期 AI 判定 | `common` `weeks` **`rank_github`** → `collect_all` | 写 `trendshift.json`；读仓库内 `数据/github-weekly/*.json` | `test_collect.py`（部分） |
| `collect_hn.py` | 取报告周 HN ≥50 分 story，去重排序、提取 GitHub 链接 | `common` `weeks` → `collect_all` `verify` | 写 `hn.json` | `test_collect.py` |
| `collect_hf.py` | Hugging Face 报告周高赞论文（②/洞察候选） | `common` `weeks` → `collect_all` | 写 `hf.json` | 无直接测试 |
| `fetch_articles.py` | 读取 HN 外链原文（标题/摘要/日期/规范链接），判定一手来源 | `tracelog` `common` → `collect_all` | 读 `hn.json`、写 `articles.json` | `test_collect_all.py`（间接） |
| `rank_github.py` | 按周榜 + HN + `judgments.json` 算 Top 5，OSS Insight 补充，写数据文件 | `paths` `tracelog` `common` `weeks` → `collect_trendshift`（反向被依赖） | 读 `trendshift.json` `hn.json` `judgments.json`；写数据文件 + `rank_report.json` | `test_rank.py` |

### 3.4 写作、交付与部署

| 文件 | 作用 | 相关性 | 状态文件 | 测试 |
| --- | --- | --- | --- | --- |
| `draft.py` | 生成草稿骨架（元数据、③ 名次、④ 候选行、数据说明），`{{ }}` 留给模型 | `collect_all` `finalize` `tracelog` `common` → 手册调用 | 读 `week.json` `materials.json`；写周报草稿 `draft.json` `report.partial.md` | `test_gates.py`（部分） |
| `finalize.py` | 刷新「数据说明」自动段、删除草稿提示注释 | `tracelog` `common` → `draft` `check_run` `verify` | 读 `collect_report.json` `rank_report.json` `week.json`；原地改写周报 | `test_gates.py` `test_check_run.py`（间接） |
| `annual_index.py` | 从实际 Git 提交提取摘要与链接，更新飞书年度表的当期记录并读回核对 | 依赖 `feishu_sync` 的 CLI 工具，供周报与月季报调用 | 按年、期间保留未确认创建标记 | `test_period_publish.py` |
| `feishu_sync.py` | 周报预检、bot 通知与 CLI 调用；旧 docx 命令留供历史排障 | `env_check`、`credential_probe` 和 `annual_index` 复用 CLI 工具 | `feishu-mode.json`、`feishu-notify-receipt.json` | `test_feishu_sync.py` |
| `deployment.py` | 确定周报模式、启动协调、验收或恢复本地沙箱；验收比较已提交正文与候选稿的字节 | 依赖 `common`、`env_check` 和 `check_run` | `deployment.json`、`acceptance.json`、`resume.json`、`local-readback.md` | `test_deployment.py` |
| `env_check.py` | 核心依赖与飞书交付依赖分开自检；check/ensure/reset 管理就绪标记 | `common` `feishu_sync` → `deployment`（延迟） | 写 `~/.ai-weekly-env.json`（**不在 WORK_DIR**） | `test_env_check.py` |
| `credential_probe.py` | 只读观测跨任务凭据/刷新证据，产出脱敏 receipt | `feishu_sync` `common` → 部署时按需运行 | 写 `~/.local/state/ai-weekly/credential-probe.json`（**不在 WORK_DIR**） | `test_credential_probe.py` |
| `trace_view.py` | 还原一周执行时间线（本地 `trace.jsonl` 或远端状态文件） | `paths` `tracelog` `common` → 无（手册/排障调用） | 读 `trace.jsonl` 或 `git show FETCH_HEAD:<state>` | 无测试 |

## 4. 配置、提示词与模板

| 文件 | 作用 | 主要消费者 |
| --- | --- | --- |
| `config/runtime.yaml` | 重试/超时、搜索次数上下限、返工轮数、协调参数、路径契约文字说明 | `check_run`（search）、`finalize`（search）、`coord`（coordination/trace）、`fetch_articles`（articles）、`collect_all`（digest） |
| `config/ranking.yaml` | 榜单阈值、排除规则、单元格长度上限 | `rank_github` `validate` |
| `config/sources.yaml` | 采集与搜索的信息源清单 | 采集脚本 |
| `config/topics.yaml` | topics / orgs 受控词表 | `validate.load_vocabulary` |
| `config/task.yaml` | 任务参数与写入白名单 | `coord`（白名单人工对齐） |
| `config/feishu.yaml` | CLI、按年配置的年度表、通知接收人 | `annual_index` / `feishu_sync` |
| `config/deployment.yaml` | 正式或验收模式 | 周报、月季报及飞书交付脚本 |
| `prompts/routine-weekly.md` | 固定入口：授权、安全边界、失败通知、写入白名单 | 自动化任务入口提示词 |
| `prompts/weekly.md` | 三段式执行手册、写作规范与失败处理 | 智能体按步执行 |
| `prompts/routine-monthly.md`、`routine-quarterly.md` | 月报与季报的固定入口，分别读取 `monthly.md` 和 `quarterly.md` | 各期独立运行 |
| `prompts/env-bootstrap.md` | 环境安装与授权流程 | 部署/排障 |
| `templates/` | 周、月、季报告模板 | 周报由 `draft.py` 生成草稿，月季报章节由 `period_report.py` 校验 |
