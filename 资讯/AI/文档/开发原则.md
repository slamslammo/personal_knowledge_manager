# 开发原则

> 本文是 AI 资讯工程的**开发约束**，不是运行手册。运行步骤看 [weekly.md](../工程/prompts/weekly.md)，内容规则看 [方案.md](方案.md)，平台安排看 [部署指南.md](部署指南.md)。
> 2026-11-19 定稿：运行时目录不固定、由提示词临时决定路径，不是生产级项目。以下原则用于消除这类不确定性。

## 1. 一条总原则

**确定性交给脚本，判断力交给模型。**

凡是「每次运行都必须一样」的东西——路径、文件名、数据格式、字段顺序、命名规则、校验规则、清理与归档——一律由脚本常量与函数产生，写进单一真值源。智能体只做两件事：

1. **按提示词执行既定步骤并验证结果**（运行脚本、读输出、按 `ACTION=` / `CODES=` 分流、报告失败）；
2. **在需要理解、分析、总结、判断、写作时才使用 AI 能力**（选题、摘要、洞察、措辞、AI 相关性判定）。

智能体**不得**自行拼接路径、发明文件名、决定中间数据落在哪里、或凭记忆推断格式。提示词与手册里不出现路径字面量，需要路径时向脚本查询。

## 2. 六条硬约束

### 2.1 单一真值源

- 仓库内产出路径、运行时根、工作目录、归档目录、状态目录，**统一由 `工程/scripts/paths.py` 定义**；脚本、手册、文档、测试都从它取，不各写一份字符串。
- 智能体查询目录用 `python3 $S/workdir.py print`，不设置、不覆盖、不猜测。
- 新增路径类型先改 `paths.py`，再加脚本；不允许先写死再回头收敛。

### 2.2 路径可预知、跨环境一致

- 运行时根由 `REPO_DIR` 推导（仓库检出目录的父级 `.ai-weekly/`），在本机与云环境都用同一条规则；绝对路径可以随检出位置变化，**推导规则与查询方式必须唯一**。
- 部署级覆盖只允许 `AI_WEEKLY_HOME` 一个变量，写在 `config/runtime.yaml` 说明里，由平台注入，**不是每次运行由智能体决定**。
- `AI_WEEKLY_TMP` 是过渡期兼容入口，PR 合并后随旧任务一起停用并删除。
- 路径不合法（空、根目录、落在仓库内、不可写）时**显式报错停止**，不静默回退 `/tmp`。

### 2.3 命名与格式固定

- 周编号一律 `{ISO 周年}-W{两位周数}`；归档目录 `archive/{WEEK}/`，**一周一份**，多次运行写进 `MANIFEST.json` 的 `runs[]`，不建 `-w40`、`-backup` 之类的手搓目录。
- 中间文件名固定（见 `config/runtime.yaml` 的 `paths.files`），脚本按常量读写；不追加周后缀、不按运行次数编号。
- 归档只留**不可再生的关键证据**（门槛结果、执行记录、搜索次数、通知文案、交付收据、最终输出），可再生数据（采集原文、素材、摘要）不归档，最终产物以 git SHA 指向。

### 2.4 状态与临时数据分层

- 跨运行状态（飞书防重 `feishu.json`、交付收据、凭据观察）**不得被清理动作抹掉**；单次运行的 scratch 可以清。
- 清理必须是**保留清单式**（`workdir.py clean`），禁止 `rm -rf <工作目录>` 整目录删除。清理前先归档本次证据。
- 手册与提示词不得出现互相矛盾的清理/保留要求。

### 2.5 可验证

- 每个路径约定、命名规则、清理行为、归档字段都有单元测试；「同一环境重复运行得到同一路径」「不同周归档不冲突」「非法值显式失败」是必测项。
- 新增约束同时补测试与文档，测试不通过不算完成。

### 2.6 变更受控

- 工程、配置、CI 改动按 [协作契约 2.1](协作契约.md#21-一轮评审与收口) 走 PR，以最终 head SHA 对应 CI 为准；合并由用户执行或明确授权。
- 入口提示词只做引导、授权与安全边界，**不为测试临时修改**；安全边界的字面调整须单独列出逐字 diff 供确认。
- 过渡期允许新旧规则并存，但必须写明停用条件与清理时机，不得无限期保留。

## 3. 职责边界速查

| 事项 | 谁负责 | 依据 |
| --- | --- | --- |
| 报告周、ISO 编号、产出路径 | 脚本 `weeks.py` / `paths.py` | 方案 2.1 |
| 运行时根、工作目录、归档目录 | 脚本 `paths.py` / `workdir.py` | 本文 2.1–2.2 |
| 目录创建、校验、清理、归档、MANIFEST | 脚本 `workdir.py` | 本文 2.3–2.4 |
| 数据采集、排名、草稿骨架、数据说明事实部分 | 脚本 `collect_*` / `rank_github.py` / `draft.py` / `finalize.py` | 方案 7.1 |
| 质量门槛、完整性检查、提交推送、飞书交付 | 脚本 `validate.py` / `check_run.py` / `coord.py` / `feishu_sync.py` | 方案 7.8、7.9 |
| 按手册执行步骤、读输出分流、报告失败 | 智能体 | weekly.md |
| AI 相关性判定、联网搜索核实、选题、摘要、洞察、写作 | 智能体（AI 判断） | 方案 7.1 |

## 4. 反模式（明确禁止）

- 在提示词里写 `export AI_WEEKLY_TMP=...` 或任何绝对路径。
- 让智能体给目录起名、按周加后缀、手工 copy 文件当归档。
- 用 `rm -rf` 清整个工作目录。
- 手册与提示词各写一份路径，靠人工保持一致。
- 路径不可用时悄悄改用 `/tmp` 继续跑。
- 把可再生中间数据长期留作「证据」。
