# 资讯

这一层是**自动化资讯板块的容器**，不是知识点库。与 `量化交易/`、`机器学习/` 等知识板块不同：这里的内容由定时任务生成，人只维护工程与规则，不手写资讯正文。

## 目录约定

每个子目录对应一个**独立定时任务**，固定四个槽位：

| 槽位 | 内容 | 谁写 |
| --- | --- | --- |
| `README.md` | 板块定位、产出体系、数据说明、导航 | 人（走 PR） |
| `工程/` | 运行时执行文件：脚本、配置、提示词、模板、依赖清单 | 人（走 PR） |
| `文档/` | 开发入口、规则、部署与变更记录 | 人（走 PR） |
| `数据/` | 周 / 月 / 季资讯、运行记录与中间数据 | 定时任务经 `coord.py` 直接推送 `main` |

判据是**运行时会不会读它**：会读的放 `工程/`，只有人和评审读的放 `文档/`，任务写出来的放 `数据/`。

## 新增板块的约束

1. 复制四槽位结构，板块名用简短中文或英文，不带「资讯」后缀。
2. **命名空间必须按板块隔离**：临时目录（如 `AI_WEEKLY_TMP`）、就绪标记（如 `~/.ai-weekly-env.json`）、验收状态目录（如 `~/.local/state/ai-weekly/`）、飞书文档标题前缀（当前为「AI 周报」）都与板块绑定；直接复制骨架会互相覆盖临时目录与凭据状态，飞书查重也会串台。
3. CI 的 `paths` 过滤、定时任务调度、飞书接收人各自独立配置。
4. **任何时刻一个板块只有一个活跃运行者**；切换平台前先停原运行者，并确认无在途实例与同步子进程。
5. 板块规则正文写在自己的 `文档/方案.md`；本文件只写这一层的约定，不放具体流程。
